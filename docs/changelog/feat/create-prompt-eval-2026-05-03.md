## Summary

Adds a prompt evaluator for the coding-agent prompt generated by `ast project create`, and improves the prompt based on eval feedback.

## Design

**Prompt eval**

`prompt_eval_test.go` (build tag: `eval`) contains a dataset of 12 agent scenarios spanning domain experts (security analyst, bioinformatics researcher, legal analyst, devops engineer, climate scientist, supply-chain manager, financial analyst, music producer, archaeologist, content moderator) plus two edge cases (no goal, gibberish goal).

Two test functions:

- `TestBuildCodingPrompt_Structure` — structural checks (prompt contains required phrases, no line exceeds 80 chars). Runs as part of the normal test suite, no API key required.
- `TestEval_Graded` — calls `claude-haiku-4-5` to score each prompt 1–10 with strengths, weaknesses, and reasoning. Skipped unless `ANTHROPIC_API_KEY` is set. Uses assistant prefill (`\`\`\`json`) and stop sequence (`\`\`\``) to extract clean JSON without post-processing. Reports per-scenario scores, average, and fails if any non-edge-case prompt scores below 5/10.

Run with:

```bash
ANTHROPIC_API_KEY=sk-ant-... go test ./cmd/ -tags eval -run TestEval_Graded -v
```

**Prompt improvements**

Based on consistent weaknesses from the first eval run (average 7.7/10), three changes were made to `buildCodingPrompt`:

- Added spec link (`https://astropods.com/schema/package.json`) and reference to `AGENTS.md` so the coding agent knows where to look when inspecting the project.
- Framed the user-supplied goal as "Initial description (confirm before treating as final)" to prevent the coding agent from treating it as settled requirements.
- Added two requirements-gathering questions: whether the initial description is accurate, and how success will be validated once the agent is implemented.

**Prompt extraction**

`buildCodingPrompt` and `wordWrap` are extracted from `create.go` into `coding_prompt.go` to isolate the prompt logic and make the trigger surface for the CI eval obvious.

**GitHub Action**

`.github/workflows/eval-prompt.yml` triggers on push and pull_request when `coding_prompt.go` or `prompt_eval_test.go` changes. It runs `go test ./cmd/ -tags eval -run TestEval_Graded -v` using the `ANTHROPIC_API_KEY` repository secret.

## Migration

No user-facing changes. The eval CI job only runs when the prompt or eval file changes.
