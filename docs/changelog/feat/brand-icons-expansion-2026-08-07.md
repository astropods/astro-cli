# Brand icon set expansion

## Summary

The agent monitor labels outbound network destinations with a brand icon, but the set only covered 62 brands, so most of what a deployed agent actually calls — inference providers, vector stores, observability backends, payment and email APIs — rendered as an anonymous row. This adds 126 more marks, weighted toward hosts that appear in real egress traffic rather than toward general SaaS recognisability. Icon ids stay keyed to the brand's registrable domain, because the client resolves an icon by taking the eTLD+1 of an outbound host and using its first label (`api.sendgrid.com` → `sendgrid`). Two optional manifest fields absorb the cases where that breaks: `domains` covers both vendors whose API host does not carry the brand name (`hubapi.com` for HubSpot, `nr-data.net` for New Relic) and hosting platforms whose customer subdomains hide it (`vercel.app`, `github.io`, `workers.dev`), and `aliases` lists non-domain identifiers — driver and protocol names an instrumentation library reports, and former names after a rebrand. Both are globally unique and validated lowercase, and they sit beside the icon because the mapping is a property of the brand, not of the consumer.

## Design

Each icon is two physically separate files, one authored per background, because the client loads them as plain `<img>` sources with no CSS context to inherit from; every file must carry a `viewBox`, since the processor drops root `width`/`height` and a file sized only by those renders as a clipped fragment. The original intent was to pass official artwork through untouched, and that is what happens for the large majority — but the rule does not survive contact with real brand kits, so two narrow exceptions are a deliberate call rather than an oversight. Where a vendor publishes no square symbol, only a horizontal lockup, the logomark is isolated by deleting the wordmark elements and refitting the `viewBox` to the remaining geometry's measured bounds; the paths themselves are never redrawn (Backblaze, Milvus, New Relic, Okta, SendGrid). Where a vendor publishes only one flat mark and no inverse, the dark variant recolours fills and nothing else, because a black mark on a near-black background is not "recorded as-is", it is missing (1Password, Cerebras, CockroachDB, Heroku, Plaid, Splunk, Telnyx, Typeform, CircleCI, Pusher). The same logic decides what happens to a backing tile: a tile in a brand colour is part of the identity and stays (Mailchimp's yellow), but a near-black tile is only a backdrop, and on a dark page it dissolves and leaves the glyph floating in nothing, so it is dropped and the glyph inverts between variants instead (Render, OpenRouter, Paddle). Rounding out the pass, oversized `viewBox`es are trimmed to the ink so a mark fills its box at 16px, and one knockout painted in literal white ink is rebuilt as a real even-odd hole so it is background-agnostic. Everything else still holds — no `currentColor`, no `<style>` or `class`, no external references, and no monochrome silhouette standing in for a brand that publishes a colour mark — and colour is now always a concrete hex on a `fill` attribute rather than an inline `style`, so that a grep for `fill=` sees the whole set instead of quietly skipping the files that styled themselves. The set is gated on a render check that measures, for every mark against both backgrounds, its ink coverage and the contrast ratio of that ink against the page; a mark is only failed when it is both low-contrast and internally flat, which is what separates an unreadable monochrome mark from a legible glyph sitting on a coloured tile.

## Migration

None — the manifest gains optional fields and consumers that only read `id` are unaffected.
