# Langfuse Integration — Second Observability Backend

## Summary

Adds Langfuse as a parallel observability backend alongside Galileo. Traces fan out to both at the collector level. Each Astro account gets its own Langfuse project, provisioned by writing directly to Langfuse's Postgres (the management API requires an enterprise license we don't have).

## Design

### Per-account project provisioning

Langfuse scopes traces to a project (determined by API keys) with no log stream concept. A shared project would mix traces across tenants, so each account gets its own project.

The provisioner (`internal/langfuse/provisioner.go`) connects to Langfuse's Postgres and lazily creates a project + API key on first deployment for an account. Key generation follows Langfuse's format (`pk-lf-{uuid}`, `sk-lf-{uuid}`) with bcrypt + SHA256 hashing. The raw secret key is KMS-encrypted and stored in `account_langfuse` for runtime use.

### Collector — dual export

The astro-collector config now has two OTLP/HTTP exporters wired into all pipelines (traces, metrics, logs). Langfuse endpoints derive from a single `LANGFUSE_BASE_URL` env var — no hardcoded defaults.

The astro processor sets `langfuse.trace.tags` as a span attribute with `deployment:{id}` so Langfuse indexes it as a filterable tag. `ASTRO_DEPLOYMENT_ID` is now the database deployment ID (not the build hash).

### Deploy-time credential injection

`deployer.Apply()` calls `EnsureProject()`, computes `base64(pk:sk)`, and passes it through `ApplierConfig` → `CollectorDeploymentConfig` → collector pod env vars (`LANGFUSE_AUTH_TOKEN`, `LANGFUSE_BASE_URL`).

### Server proxy endpoints

Deployment-scoped endpoints that proxy Langfuse's REST API using per-account credentials:

```
GET /api/v1/deployments/:id/observability/traces
GET /api/v1/deployments/:id/observability/metrics
GET /api/v1/deployments/:id/observability/summary
```

Auth resolves the deployment by ID, checks account membership, then queries Langfuse filtered by `deployment:{id}` tag.

### Deployment image auto-tagging

`moon run deployment:collector` and `deployment:messaging` now auto-tag images as `astropods/collector:latest` and `astropods/messaging:latest`, eliminating the manual `docker tag` step.

## Migration

- Set `LANGFUSE_DB_URL`, `LANGFUSE_SALT`, `LANGFUSE_ORG_ID`, and `LANGFUSE_BASE_URL` on astro-server.
- Run the `account_langfuse` migration (`sql/astro-server/schema.sql`).
- Rebuild the collector image (`moon run deployment:collector`).
- No changes needed for existing agents — Langfuse projects are provisioned lazily on next deploy.
