## Summary

The `/install` shell script served by `astro-server` had several gaps: it silently skipped checksum verification when no entry was found, only printed a PATH reminder instead of writing to the shell config, left v-prefixed versioned binaries behind on cleanup, and had no way to distinguish a fresh install from an upgrade.

## Design

Five fixes to the script generated by `CLIInstallScript` in `handlers/cli.go`:

- **PATH injection**: instead of printing a reminder, the script now detects the active shell (`$ZSH_VERSION` / `$SHELL`) and appends `export PATH="$HOME/.ast/bin:$PATH"` to `.zshrc`, `.bashrc`, or `.profile`. A `grep` guard prevents duplicates on re-runs.
- **Hard fail on missing checksum**: if `grep "$BINARY_NAME"` returns nothing, the script removes the temp file and exits 1 with `No checksum found for <name>`. Previously the empty `$EXPECTED` caused the entire checksum block to be silently skipped.
- **Cleanup glob covers v-prefixed versions**: the `for` loop now matches both `${PREFIX}-[0-9]*` and `${PREFIX}-v[0-9]*`, and adds a `[ -e "$f" ] || continue` guard for empty globs.
- **Upgrade vs fresh install messaging**: before downloading, the script checks whether an existing binary is present and prints `Upgrading from X to Y` or `Downloading` accordingly.
- **Post-install verification**: after linking the binary, the script runs `$PREFIX --version` and prints `<prefix> is ready` or a failure message.

A `cli_test.go` is added alongside `cli.go` covering all five behaviours, plus `CLIDownload` (redirect, unknown name, path traversal, empty base URL).

## Migration

Nothing required. The changes are to the dynamically generated script — any `curl … | sh` invocation picks them up automatically.
