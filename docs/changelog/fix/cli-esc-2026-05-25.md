# Uniform cancel UX across astro-cli interactive prompts

## Summary

Interactive prompts and TUIs in `astro-cli` had inconsistent cancellation: some surfaces never told users how to quit, three huh forms (`secrets create`, `secrets update`, the username claim in `login`) propagated `ctrl+c` as a command-failure exit code, others silently swallowed errors, and bubbletea TUIs disagreed on which keys quit (`q` worked in `repair`, `esc` only in `configure`, neither anywhere else). This change makes every interactive surface accept the same keys, advertise them with the same footer line, and translate cancellation into a clean exit code.

## Design

A single shared package, `internal/tui`, holds the canonical pieces:

```go
// internal/tui/cancel.go
var ErrCancelled = errors.New("cancelled")
var Cancel = key.NewBinding(
    key.WithKeys("esc", "ctrl+c"),
    key.WithHelp("esc", "cancel"),
)
func Help(theme *huh.Theme) help.Model       // styled help.Model
func Hint(theme *huh.Theme, bindings ...key.Binding) string  // " • " joined short help
```

**huh forms** (everything except `configure`) route through `cmd/runForm`. It applies a shared keymap binding both `esc` and `ctrl+c` to Quit, wraps the form in a small `promptModel` that delegates to huh and translates abort/complete into `tea.Quit`, and maps `huh.ErrUserAborted` to `tui.ErrCancelled`. The hint is rendered **on its own line below huh's per-field footer** via `tui.Hint(cliHuhTheme(), tui.Cancel)` — putting it on a separate line makes the rendering reliable regardless of whether huh's footer is one key wide (single-field Inputs) or several (Selects with filter), and side-steps the form's internal viewport clipping the right edge of the previous line.

**`ast configure`** is the one exception. It needs `ctrl+r` to toggle reveal/hide on the focused secret field, which requires rebuilding the underlying `huh.Form` mid-flight to swap `EchoMode`. So `configureApp` stays as a thin bubbletea wrapper that intercepts `tab/shift+tab/ctrl+r/esc` before huh sees them. To avoid huh's per-field footer contradicting the wrapper's actual key surface, the form is built with `WithShowHelp(false)` and `configureApp.View` renders one footer line itself using the same `tui.Hint(cliHuhTheme(), …, tui.Cancel)` helper — so the styling matches every other form.

**Bubbletea-only TUIs** (`internal/tui/credentials`, `internal/tui/repair`) call `tui.Hint(nil, …, tui.Cancel)` to render their footer with `help.New()` defaults. They return `tui.ErrCancelled` on quit; callers (`cmd/repair.go`) branch on `errors.Is` and exit 0. `repair` drops its old `q` binding since `q` was never advertised and conflicted with text-input intent in adjacent code.

**Callers** uniformly translate `tui.ErrCancelled` into a graceful exit with a `Cancelled.` line via `cmd.printCancelled(w)`.

Key decisions:

- **`esc` is the canonical cancel key.** `ctrl+c` is also accepted everywhere as a standard reflex; `q` was removed (only ever bound in `repair`, which is `Hidden: true`).
- **Cancellation is never a command failure.** All sites that previously returned `huh.ErrUserAborted` (or any error) on user abort now exit 0.
- **Hint on its own line.** Inline-appending the hint to huh's footer line is fragile (depends on huh's last rendered line being the footer, which only holds when `WithShowHelp(true)` and which gets clipped by the form's internal viewport width). Rendering the hint on a fresh line below the form makes the layout identical across every command.

## Related fixes

Two adjacent UX issues were folded into the same change because the cancel rework made them obvious:

- **`ast push` visibility prompt moved before `Build`.** Previously `ResolveVisibility` ran after build and image push, so declining the visibility change wasted minutes of build work. The step only depends on `cfg` (account/agent name/visibility/yes flag), so it now runs right after `ParseSpec` / `CollectComponents` and before any expensive step.
- **`ast create` no longer emits the coding prompt on cancel.** The form-cancel branch used to fall through to print "Paste this into Claude…" with an empty goal. It now returns early on any `runForm` error (including `tui.ErrCancelled`), matching what cancel means everywhere else.

## Test plan

Each interactive surface should be verified for (a) the footer line ends with `esc cancel`, (b) pressing `esc` aborts with `Cancelled.` (or equivalent graceful exit), (c) pressing `ctrl+c` does the same, (d) completing normally still works.

### Huh forms (via `runForm` → `promptModel`)

- `ast account switch` (no arg, with >1 stored account) — Select form
- `ast secrets create <name>` (omit `--value`) — two-field Input form
- `ast secrets update <name>` (omit `--value` on an existing secret) — two-field Input form
- `ast agent delete <name>` (omit `--confirm`) — Confirm
- `ast blueprint push` *or* `ast blueprint deploy` when visibility actually changes (public↔private) and `--yes` is not set — Confirm
- `ast login` for a brand-new account with no existing username — Input with async validation
- `ast create <name>` interactively (omit any prompt-skip flag) — single-field Input
- `ast configure` interactively while a `.env` file exists — Confirm (Yes, delete / Keep it), appears after the main form completes

### Bubbletea TUIs (each renders its own footer)

- `ast configure` main form — verify `tab/shift+tab navigate • ctrl+r reveal • esc cancel` (or `hide` once revealed) renders on its own line below the body; `esc` and `ctrl+c` both abort; `ctrl+r` still toggles reveal on secret fields
- `ast spec repair` (hidden) — verify `↑/↓ navigate • space toggle • enter confirm • esc cancel` footer; `esc` aborts; `q` no longer quits (regression check)

### Edge cases

- **Filter mode in `ast account switch`**: press `/` to enter filter, type, then `esc` — form-level Quit wins so the form aborts rather than clearing the filter. Same behavior as before this change.
- **Validate failure in `ast login`**: type an invalid username, let server-side validation reject, then `esc` — should still cancel cleanly without surfacing the validation error.
- **`ast spec repair --yes`** — should skip the TUI entirely.

## Migration

No user-facing migration. Anyone scripting against exit codes will see `ast secrets create`, `ast secrets update`, and `ast login` now exit 0 on `ctrl+c` where they previously exited non-zero — this matches the rest of the CLI and is the intended fix.
