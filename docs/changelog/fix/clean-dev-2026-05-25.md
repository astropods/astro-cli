# Local dev scripts: fixes for clean repo checkout

## Summary

A fresh `git clone` followed by `scripts/local-dev.sh` failed in three distinct ways depending on what state your machine started in. None of these were code bugs — all three were scripts assuming state that only exists after the repo has been brought up at least once before. This change makes the local-dev bootstrap idempotent and survivable on a brand-new checkout.

## Design

Three independent fixes, all in shell scripts:

- **Atlas URL separator (`apps/astro-server/scripts/dev.sh`).** The schema-apply step appended `&search_path=public` to `DATABASE_URL` unconditionally. When the URL had no existing query string (the common case on a fresh `.env`), the result was a malformed URL and Atlas rejected it. The script now picks `?` or `&` based on whether `DATABASE_URL` already contains a `?`.

- **OpenMeter plan re-bootstrap (`scripts/bootstrap-openmeter.sh`).** Creating the `private_beta` plan on a fresh OpenMeter succeeds, but re-running the bootstrap script (which any clean checkout will do via `local-dev.sh`) failed because the plan already existed. `GET /api/v1/plans/{key}` returns 404 for draft-only plans so it can't be used to detect the existing record. The script now checks `GET /api/v1/plans?key=private_beta` and short-circuits with success when `totalCount > 0`.

- **Workspace package builds (`scripts/local-dev.sh`).** `apps/astro-client`'s `bun install` resolves workspace deps against built artifacts. On a clean checkout those artifacts don't exist yet, so the install step fell over on missing `astro-theme` / `astro-trading-card` outputs. The script now runs `moon run astro-theme:build astro-trading-card:build` before the client install.

## Migration

None. Re-run `scripts/local-dev.sh` from any state.
