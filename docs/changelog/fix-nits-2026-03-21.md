# fix-nits — Deploy Page Styling Fixes

## Summary

Polish pass on the deploy page detail view addressing visual inconsistencies in status display, color usage, table alignment, and control styling.

## Design

- **Status label**: The STATUS info card now shows a human-readable mapped label ("Deploying", "Live", "Inactive", "Error") instead of the raw API status string. This also fixes a bug in `mapDeploymentStatus` where deployments with `ready=0` and `replicas>0` were classified as "error" even when the status string explicitly indicated a deploying/pending state — explicit status strings now take precedence over the readiness heuristic.
- **Color consistency**: "Deploying" state is now consistently amber/yellow across the header badge, status card, and table rows. The "Monitor" and "Deployments" section headers are now `text-foreground` instead of teal.
- **Table alignment**: Duration, Build No., and Deployed on columns are right-aligned in both headers and values. These values also use `text-foreground` color instead of muted/faint, as do the corresponding columns in the traces table (time, latency, tokens, external ID).
- **Pause button**: Styled as a destructive action with coral border and text color.
- **Cosmetic**: Removed the "No prior deployments yet" placeholder from the history table. Normalized the Find in Logs search bar height and font size to match the time range dropdown.

## Migration

No changes required.
