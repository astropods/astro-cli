# Point the CLI submodule at 0.16.1

## Summary

The prod CLI release cannot run against the current pointer.

`release-cli-prod.yml` reads `modules/astro-cli/VERSION` and refuses a version
already published:

```
Version 0.16.0 is already released to s3://prod-astro-downloads. Bump the VERSION file before releasing.
```

The pointer names `4d928c7`, which still carries `0.16.0`.
`https://download.astropods.ai/latest/VERSION` returns `0.16.0`, so the guard
fires and the release stops.

## Design

The pointer moves to `4ffb5a2`, the CLI repository's current tip. `4d928c7` is an
ancestor of it, so this is a fast-forward and no CLI work is skipped.

Three things come with it beyond the version itself:

- `VERSION` becomes `0.16.1`, which the release reads and the self-upgrade check
  compares against. Leaving it at `0.16.0` means no installed CLI is ever offered
  the update, because `fetchLatestVersion` compares the published file to
  `buildinfo.Version` and finds them equal.
- Local dev mode reports on-demand ingestions separately from started services.
- Local dev mode fails fast when an agentcore agent never binds the contract port,
  rather than waiting out a timeout with no explanation.

Nothing in the monorepo changes: no Go module, no build target, no server
behaviour.

## Migration

None. Rebuild to pick it up:

```
moon run astro-cli:link           # ast-dev, localhost
moon run astro-cli:link-preview   # ast-preview, astropod.ai
```
