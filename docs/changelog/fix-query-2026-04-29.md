## Summary

Navigating to `/blueprints?account=<name>` triggered an infinite refetch loop that prevented blueprint cards from loading. The `useAccountBlueprints` query would be canceled repeatedly, preventing any data from appearing.

## Design

`ActiveAccountProvider` created a new `setActiveAccount` function reference on every render because it was defined as a plain inline function. `Blueprints.tsx` lists `setActiveAccount` in its `useEffect` dependency array — every new function reference caused the effect to re-run, which called `setSearchParams({}, { replace: true })`. Each `setSearchParams` call triggers a React Router navigation, which cancels the in-flight `useAccountBlueprints` fetch and starts a new one, which gets canceled again on the next render in an infinite loop.

Fix: wrap `setActiveAccount` in `useCallback` with `[personalAccount?.name]` as its dependency. The function reference is now stable across re-renders and the effect fires exactly once per account change.

A Playwright regression test was added covering the full breadcrumb navigation flow: blueprint detail → breadcrumb account link → blueprints list → card click → back to detail. If the refetch loop regresses, cards will never load and the test fails.
