# Local dev: signal handling, port-forward hygiene, smoke-test fix

## Summary

`scripts/local-dev.sh` was leaving orphaned grandchildren (astro-server, fakeopenmeter, bun dev) bound to launchd whenever the script exited via Ctrl+C, so the next run hit "port in use" errors until the user manually pkill'd them. At the same time, `scripts/agent-k8sfwd.sh` defaulted its host port to `8090`, which collides with Traefik when the local docker-compose stack is running. The post-deploy smoke test also broke because `ast agent delete` now requires `--name` / `--id`. This batches the three local-dev fixes with a routine submodule bump.

## Design

**Signal propagation through the local stack.** `local-dev.sh` enables job control (`set -m`) so each backgrounded subshell gets its own process group, and the cleanup trap now signals the whole group (`kill -- -$pid`) instead of just the subshell PID. `apps/astro-server/scripts/dev.sh` drops its own trap and `air &` indirection in favor of `exec air` — replacing bash so air receives parent signals directly, with enough time to kill its astro-server child (which runs in its own pgroup via `Setpgid:true`). The two scripts now cooperate: `local-dev.sh` owns the outer cleanup, `dev.sh` is a thin signal-forwarding shell.

**Targeted port-forward cleanup + non-colliding default port.** `agent-k8sfwd.sh` defaults to host port `18090` (overridable via a second positional arg) so it no longer fights Traefik on `8090`. The blanket `pkill -f "kubectl port-forward"` was scoped to `kubectl port-forward .*${AGENT}-`, so re-running for one agent doesn't kill forwards for unrelated agents. kubectl's "Forwarding from…" async output is discarded and the background job is `disown`'d so its state changes don't land on the prompt.

**Smoke test alignment with new CLI surface.** `apps/tests/smoke/cli.teardown.ts` was calling `ast agent delete 'Hello Astro' --confirm 'Hello Astro'`; the CLI moved positional targets to `--name`/`--id` (see `apps/astro-cli/cmd/agent_target.go`), so teardown was failing with `unexpected argument "Hello Astro" — use --name or --id`. Updated to `ast agent delete --name 'Hello Astro' --confirm 'Hello Astro'`.

**Submodule bump.** `modules/adapters`, `modules/agents`, and `modules/astro-infra` are advanced to their latest `main`. No source changes in this repo.

## Migration

No action required. If you ran the old `agent-k8sfwd.sh`, the default forward now lands on `localhost:18090` instead of `:8090` — update any local bookmarks or override with `agent-k8sfwd.sh <name> 8090` to restore the prior behavior.
