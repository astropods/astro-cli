## Summary

This change refines deployment detail and monitor trace UX for readability and consistency. It standardizes status presentation, control sizing, and alignment, and improves local iteration by ensuring trace-table states are visible without relying on live observability data.

## Design

The deployment detail view now uses tighter visual hierarchy and consistent interaction affordances: status/value alignment was corrected, build emphasis reduced, and controls in logs/tooling rows were normalized to shared dimensions. Deploying-state visuals were harmonized to warning-token semantics where intended, while preserving neutral text in summary contexts that should remain non-semantic.

Monitor traces were updated to improve scanability: row values use consistent sizing, status cells are left-aligned with their header, external ID actions are pinned for vertical alignment, and status labels use a lightweight inline badge treatment with token-driven coloring. This keeps states recognizable without oversized badge chrome.

For local development, observability mocking was expanded so traces/summary/metrics paths can populate monitor views deterministically. A dev fallback trace set also ensures UI review remains possible when backend trace payloads are empty.

## Migration

No migration is required. Changes are UI and mock-data behavior updates only, with no API contract changes for production clients.
