## Summary

The eval review queue now supports loading beyond the first backend page. This prevents reviewers from reaching a false "all caught up" state after judging the initially loaded traces while more unreviewed traces still exist later in the queue.

## Design

The review queue query now uses TanStack infinite pagination. The first page establishes the backend snapshot with `end_time`; each additional page uses the returned `next_offset` together with that same snapshot token so pagination stays within one consistent trace window. Queue pages stay at 50 traces so each Langfuse fetch remains bounded while still giving reviewers a manual way to continue.

The UI keeps review actions optimistic across all loaded pages. Judging a trace removes it from whichever loaded page contains it, while the queue still remembers whether the server has more pages available. When visible rows remain, reviewers can use a subtle "Load more items" button at the bottom of the queue list. When the loaded page has been fully judged but `next_offset` is still available, the detail panel invites the reviewer to load the next page instead of showing the final caught-up state.

If an infinite-query page returns no visible queue items but the backend still reports another page, the review queue automatically skips ahead a bounded number of times before falling back to the manual load-more control. This keeps reviewers moving past pages that only contain already-judged traces without creating an unbounded fetch loop.

Review-detail navigation shows the current trace position and loaded queue size without header chevrons. Reviewers can use the queue list itself to move between traces, keeping the header focused on orientation rather than duplicate controls.

Undo behavior stays optimistic as well: it restores the trace into the loaded queue cache without refetching the review queue, avoiding a replay of every loaded page's Langfuse fetch and sentiment annotation. Quick undo from the review queue restores the trace to the loaded page it came from; removals from the Dataset view synthesize the queue row from the dataset item and place it in the visible queue cache when one is loaded.

## Migration

No migration is required.
