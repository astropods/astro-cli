## Summary

Two bugs in the agent detail view: (1) clicking Redeploy from the "new build available" CTA was deploying the old build instead of the new one, and (2) the configure panel scrolled with the page instead of staying fixed.

## Design

**New-build redeploy fix** — `latestBuildId` was computed in `ActiveDetailView` but never forwarded to `ConfigurePanel`. The panel fetched the deployment template (which contains the old `source.build`) and deployed with that. Fix: add a `newBuildId` prop to `ConfigurePanel`; when set, patch `template.source.build` before the template reaches the form or deploy call. `ActiveDetailView` passes `latestBuildId` when `configIsNewBuild` is true.

**Upgrade banner** — when `isNewBuild` is active the panel shows a yellow context banner (`Update · <old 8-char hash> → <new 8-char hash>`) consistent with the existing rollback/readOnly banners.

**Configure panel scroll fix** — the root layout uses `min-h-screen` which allows page-level scroll, breaking `position:sticky` on the panel. Fix: `ActiveDetailView` locks `document.body.overflow = hidden` on mount (restored on unmount), and the right panel uses `position:fixed` anchored at `top:56px` (below the 56px AppHeader) with `height: calc(100vh - 56px)`. An in-flow spacer div stays in the flex layout to drive the existing width open/close animation.

**Footer pin fix** — the configure panel footer (Discard/Redeploy) was buried under the master scroll. Removed `sticky bottom-0` from the footer and `pb-24` workaround padding; the panel shell is `flex flex-col h-full` so the footer is a natural `shrink-0` flex child pinned at the bottom while the form content scrolls independently.

## Migration

No changes required.
