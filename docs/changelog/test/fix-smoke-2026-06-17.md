# Fix marketing homepage smoke tests

## Summary

The marketing site redesign changed the homepage hero and navigation, breaking
four production smoke tests in `apps/tests/smoke/public.spec.ts`. The old tests
asserted on copy and CTAs that no longer exist on `/`.

## Design

The redesigned homepage (`modules/website`) replaced the prior surface:

- Hero headline is now "Where agents become teammates." (was
  "Agent-native infrastructure").
- The install command / "Copy install command" button and the signup "Get
  started" CTA were removed from `/`. The primary conversion CTA is now
  "Book a demo" (Google Calendar scheduler), alongside a "Login" link to the
  app. The CLI install surface moved off the homepage; `/builders` is not a
  reliable target in production because that path resolves to a reserved
  account/app route, not the marketing page.
- Discord now appears in both the nav and the footer, so the unscoped
  `getByRole("link", { name: /discord/i })` locator became ambiguous.

Test changes:

- Hero assertion targets the new headline via an accessible heading role.
- Dropped the install-command test (CLI install is still covered end-to-end by
  `cli.spec.ts`, which runs `curl -fsSL https://astropods.com/install | sh`).
- Replaced the signup-CTA test with "Book a demo" (links to the scheduler) and
  "Login" (links to the app) checks reflecting the homepage's real CTAs.
- Scoped the Discord external-link check to `.first()`.

## Migration

None. Test-only change.
