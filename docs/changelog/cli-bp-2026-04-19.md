# ast push: visibility flags

## Summary

`ast push` now controls blueprint visibility through explicit `--public` and `--private` flags. The `visibility` field in `astropods.yml` is no longer read or respected. This makes visibility an intentional, per-push decision rather than a spec-level default that could silently change a blueprint's exposure.

## Design

Two mutually exclusive flags are registered on the push command:

- `--public` — makes the blueprint visible to everyone on the global catalog
- `--private` — keeps the blueprint visible only to the owning account (default)

If neither flag is given, the push defaults to `private`. If the blueprint is already public on the server and no explicit flag is passed, the existing public visibility is preserved without prompting.

Before applying a visibility change, the CLI fetches the blueprint's current visibility from the server. A confirmation prompt appears when:

1. Making a blueprint public that isn't already public (new blueprint or direction change), or
2. Explicitly downgrading a public blueprint to private with `--private`.

| Scenario | Visibility used | Prompt? |
|---|---|---|
| No flags, new blueprint | private | no |
| No flags, already private | private | no |
| No flags, already public | public (preserved) | no |
| `--public`, new blueprint | public | yes |
| `--public`, already public | public | no |
| `--public`, was private | public | yes |
| `--private`, was public | private | yes |
| `--private`, new blueprint | private | no |

The prompt copy is context-aware — it describes exactly what is changing (e.g. "This will change the blueprint from private to public, making it available to everyone."). On refusal the push exits with `push cancelled`.

Public blueprints are indexed by the global catalog (`/blueprints/discover`), which queries all blueprints with `visibility = 'public'` across all accounts. Private blueprints only appear in the owner's personal view.

## Migration

Users who set `meta.visibility` in `astropods.yml` must now pass `--public` explicitly at push time. The spec field is silently ignored; no error is raised for leaving it in place.
