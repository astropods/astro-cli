## Summary

The `astropods.yml` generated by `ast-dev create` was missing the required `meta` field, causing `ast-dev push` (and `ast validate`) to fail with a JSON schema error immediately after project creation.

## Design

The JSON schema derived from `AstroSpec` marks `meta` as required because its struct tag has no `omitempty` (`json:"meta"`). The scaffold template (`templates/template-ts/astropods.yml`, shared by both `mastra` and `langchain`) never emitted this field. The Go YAML parser silently defaults missing struct fields to their zero value, so `spec.ParseSpec` passed — but the stricter JSON schema validator used by `ast-dev push` rejected the output.

The fix adds `meta` with `visibility: private` as a default to the shared template. A new test in `cmd/template_test.go` renders the template for each scaffold type and runs it through the full `validateSpecFile` pipeline (JSON schema + semantic), the same path taken by `ast validate` and `ast-dev push`.

## Migration

Nothing required. Existing `astropods.yml` files that already have `meta` are unaffected. Newly created projects will include `meta:\n  visibility: private` by default.
