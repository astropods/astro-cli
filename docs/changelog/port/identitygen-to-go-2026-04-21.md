# Port identitygen from TypeScript to Go

## Summary

Agent placeholder SVGs are generated by `packages/astro-identity-gen` (TypeScript). The server needs to own this generation so avatars can be rendered server-side without invoking a JS runtime. This change lifts the generator into `apps/astro-server/internal/identitygen/` as a pure Go port. Integration (HTTP handler, client swap, deleting the TS package) is a separate follow-up.

## Design

The port aims for **visual equivalence**, not byte-exact SVG parity. Two tiers of parity requirements fall out naturally:

- **Exact (qualitative):** `hash()` and the Mulberry32 `rng` sequence must be bit-identical to the TS reference. One bit of drift reseeds the PRNG or shifts a `Math.floor(rng() * n)` index, swapping a palette or edge style and producing a completely different identity.
- **Tolerant (quantitative):** Geometric floats (`rotation`, `radius`, path coordinates, etc.) and SVG string formatting tolerate last-ULP drift. Go's `math.Cos`/`math.Sin` and `strconv.FormatFloat` produce values that differ by at most one unit in the last place vs. JS — imperceptible at any render size.

This split eliminates the usual porting hazards (no JS `Number.toString` replica, no byte-exact golden fixtures, no libm compatibility layer).

### Package layout

```
apps/astro-server/internal/identitygen/
  rng.go         — djb2 hash (UTF-16 iteration) + Mulberry32 PRNG
  theme_data.go  — generated: 12 palettes × 11 shades + ordered palette/shade lists
  polygon.go     — flat / spikey / scalloped / inverse-scalloped path builders
  eyes.go        — 8 eye styles
  generate.go    — GenerateIdentity, GenerateCustomIdentity, internal identityChoices helper
  testdata/      — hash_rng.json, choices.json parity fixtures (captured from TS)
```

### Testing strategy

Three layers, all objective:

1. **Hash + rng parity.** 20 seeds captured from TS → bit-exact `hash()` output and bit-exact first 100 `rng()` outputs (IEEE 754 bit patterns stored as hex in `hash_rng.json`).
2. **Choices parity.** For the same seeds × 3 sizes, the TS reference records every decision `generateIdentity` makes (palette, shade, sides, edge style, eye styles, and the geometric floats). Go asserts exact equality on discrete fields and `1e-9` tolerance on floats via the internal `generateIdentityWithChoices` helper.
3. **Structural SVG checks.** Output parses as valid XML, contains the right background/foreground colors, the expected eye count, and the full 4×8 custom-options matrix renders cleanly.

### Fixture generation

Two one-shot TS scripts (`packages/astro-identity-gen/scripts/gen-theme.ts` and `gen-parity-fixtures.ts`) transcribe palette data into `theme_data.go` and dump parity fixtures into the Go `testdata/` directory. These run rarely — TS is the source of truth until the follow-up PR deletes it; after that, the frozen fixtures continue to be the spec.

### TS-side change

The existing `packages/astro-identity-gen` package is otherwise untouched, except that `generate.ts` now exposes a `generateIdentityWithChoices()` function alongside the original `generateIdentity()`. The original delegates to the new function, and its existing public API and output are unchanged.

## Migration

No migration required. The Go package exists but nothing calls it yet. A follow-up PR will wire it into a server handler and migrate the client off the TS package.
