# WorkOS Organization & User Event Sync

## Summary

The WorkOS events consumer previously only handled `organization_membership` events. This left gaps where organization-level changes (renames, deletions) and user deletions in WorkOS were not reflected locally.

## Design

Extended the `EventsConsumer` to subscribe to 6 additional event types across two categories:

**Organization events** (`organization.created/updated/deleted`):
- `created` — handles three cases: already linked (skip), Astro-created with `external_id` (link only), or externally-created (create ownerless local account + link). Uses new `AccountStore.CreateWithoutOwner()` to avoid requiring an owner for externally-provisioned orgs.
- `updated` — syncs name changes back to the local account via `Rename()`.
- `deleted` — soft-deletes the account by setting `deleted_at` (new nullable column on `accounts`) rather than hard-deleting, so active deployments and agents can be cleaned up later.

**User events** (`user.created/updated/deleted`):
- `created`/`updated` are no-ops since there is no local users table.
- `deleted` removes the user from all `account_members` rows via new `AccountStore.RemoveUserFromAllAccounts()`.

The event processing was refactored from a single `processEvent` switch into three focused handlers (`processMembershipEvent`, `processOrganizationEvent`, `processUserEvent`) dispatched by event prefix.

**Schema change**: `accounts.deleted_at` (nullable timestamp) added to support soft-delete.

## Migration

Atlas will add the `deleted_at` column automatically. No data migration needed — existing rows will have `NULL` (not deleted). Queries that filter active accounts should add `WHERE deleted_at IS NULL` as cleanup logic is implemented.
