# 2026-08-19.1

## Billing

This release fills the gap between "your payment failed" and "you are running
again", and it stops two ways an account could be charged for something it does
not owe.

- **Finish a payment your bank stopped.** A charge that needs bank
  authentication now offers a Complete payment button that opens the payment
  page. Previously the banner told you to update a card that was working, and
  doing so changed nothing.
- **Adding a card pays what you already owe.** Saving a working card on a
  stopped account charges its open invoices immediately. It previously waited on
  the payment provider's own retry schedule, which can be days out or already
  finished, so the account stayed stopped with a good card on file.
- **Free credit is granted once per person.** The $10 signup credit belongs to
  you, not to each account you create. Creating a second organization no longer
  grants a second credit. Those accounts run on the same rates with no starting
  credit.
- **Spend controls show the number they are measured against.** The card read
  `$0.00` for an account with real usage, because it showed spend after credit
  while the controls trigger on spend before credit. It now reads usage spend
  and says so. A non-zero figure also printed at a hundredth of its value.
- **The spend warning reaches you.** Crossing your own warning threshold now
  sends a message. It previously changed a badge on the billing page and nothing
  else. Both the warning and the limit state the amount spent and the threshold
  you set.
- **Your plan is on the billing page.** The billing settings page names which
  plan the account is on, read from the live contract. An account that has not
  finished setting up reads "Not set up" rather than a plan name.
- **Compute is billed once.** A retry in the usage meter could charge the same
  minutes twice, overcharging the affected window by half. Usage is now billed
  on fixed five-minute windows, so a repeat cannot add anything.
- **An invoice with no PDF says so.** Opening one previously claimed the invoice
  was still a draft while the badge beside it read finalized.
- **A card removed outside the app is recorded.** Deleting a card from the
  payment provider's dashboard left the account looking like it still had one.

Billing enforcement is live in preview only. Production is unchanged.

## Insights

- **See what Claude Code was used for, not just what it cost.** Every prompt is
  labelled by purpose (work, personal, or ambiguous) and by topic across 15
  categories. Clicking the Claude Code row opens a breakdown of spend by
  category over time, and names the developers behind it. Selecting an arc, a
  legend row, or a day narrows the page. Admins see everyone; members see
  themselves.
- **Coverage is stated, not guessed.** Prompts with no labels, labels with no
  cost, and no usage at all are three different situations with three different
  answers, and the page distinguishes them instead of showing one empty chart.
- **The page reads a durable daily store.** The old path recomputed 90 days of
  history every six hours and served it from a cache. That path is gone, along
  with the Faster Insights experiment that let you compare the two.
- **Tables follow the range you picked.** The agents and Users tables scope to
  the selected window instead of always showing 90 days.
- **The page ends at the last complete day** and the footer names that day.
- **Accounts with more than 100 agents get complete tables.** The old path
  stopped at 100.
- **Period-over-period change survives dev-tool spend**, which the old path
  discarded.
- **"People" is now "Users."** The tab lists bots and agent identities alongside
  people, so the old label undersold it.

## Fine-grained deployment access

- **Read access is enforced.** With Fine-grained access on for an organization,
  a member needs `deployment:read` to see or open an agent. That covers lists,
  counts, summaries, the detail page, and every control-plane tab: status,
  runtime, files, logs, observability, configuration, and network. A denied read
  reads as not found.
- **A new agent stays visible while its access is set up.** It shows a "Setting
  up access" state that resolves on its own, instead of disappearing or opening
  into an authorization error. A setup that stalls offers a retry.
- **Owner is now Admin** on a deployment. Organization and account ownership are
  unchanged.

Access-management screens still ship in a later release. Production keeps
fine-grained access disabled.

## Traces

- **Trace cost is correct again.** Costs live on the individual model calls
  inside a trace, and both the list and the detail panel now total them instead
  of reading a parent that always holds zero.
- **A trace is one row in the list.** Child steps briefly appeared as though each
  were its own trace, and trace timestamps rendered as an invalid date.

## Evals

- **Review queues cover the most recent 30 days.** A large trace history could
  make the queue fail to load at all.
- **The dataset item list drops the Good/Bad verdict.** The UI stopped offering
  that filter, so the query parameter and its cursor pagination are removed.

## Deploying and running agents

- **The deploy failure banner names the container that failed.** An agent with a
  sidecar previously reported the generic cause with no way to tell which
  container broke.
- **Pod events lead with a severity icon.** Severity previously came through as
  a thin colored bar, which is easy to miss and unreadable without color. Each
  icon carries a label for screen readers.
- **A rejected agent name explains the rule it broke.** The message was
  hardcoded and described rules the platform does not enforce, including the
  wrong minimum length.
- **Unused CPU and Unused memory alerts are switched off.** Both fired on
  healthy agents, because an idle agent looks identical to an over-provisioned
  one, and both advised cutting a reservation that may be right for the agent's
  peak.

## Organization members

A member could show up in the member list as a raw user ID, and the same row
rendered blank in the access picker. Membership is now mirrored only for people
who have finished onboarding, and it completes the moment they do. People who
were invited but have not accepted are named by the address they were invited
at. Anything still unresolved renders as "Unknown user" with a placeholder
avatar, and the row stays fully manageable.

## CLI 0.16.1

- **A billing refusal reads as a billing refusal.** A gated command printed raw
  JSON and exited 1. It now prints the reason and the fix and exits 3, so a
  script can tell a billing refusal from any other failure.
- **Local dev mode reports on-demand ingestions** separately from started
  services, and fails fast when an agentcore agent never binds its port instead
  of waiting out a timeout with no explanation.

### Langfuse v4

- **#2008** (`langfuse-v4-migration`): v4 replaces the `traces`/`observations`
  ClickHouse tables with `events_full` and deprecates the v1 read APIs.
  `client.go` selects a `traceReader` (`v3Reader` / `v4Reader`) once in
  `NewClient`, so retiring v3 means deleting one branch. Behaviors found by
  testing against a live v4 instance, not from documentation: `/v2/observations`
  silently ignores `tags`, `fromTimestamp`/`toTimestamp`, and `orderBy`, so
  filtering goes through the JSON `filter=` array and sort is client-side;
  `fields=` is additive; pagination is opaque-cursor; `/v2/metrics` has no
  `view:"traces"`, and `isRootObservation=true` must not apply to cost or token
  measures, which live on child `GENERATION` spans; grouping by a high-cardinality
  dimension needs `orderBy` and a `config.row_limit` capped at 1000 server-side,
  which is a real ceiling for the Insights roll-up's per-user grouping.
  `provisioner.go` needs no change, since the `organizations`/`projects`/`api_keys`
  schema is unchanged between v3.221.1 and v4.11.0.
- **#2026** (`fix/langfuse-v4-root-detection`): three defects, all from sending a
  v3-shaped request to a v4 endpoint. Root selection moves into the filter array
  as `{"type":"boolean","column":"isRootObservation","operator":"=","value":true}`,
  which Langfuse resolves to `(parent_span_id = '' OR is_app_root)` and therefore
  also matches a root whose parent was never ingested. Traces are keyed by
  `traceId`, not by the root span's ID. Field groups are requested explicitly;
  the missing `trace_context` group caused every trace detail to `404`, because
  `GetLangfuseTraceDetail` rejects a trace whose tags omit the caller's
  deployment, and left `CreatedAt` empty. A test decodes a literal response body
  so a wrong key fails the build.
- **#2027** (`fix/langfuse-v4-trace-cost`): `getTraces` follows its
  `/v2/observations` page with one `/v2/metrics` call grouped by `traceId`,
  filtered to that page's IDs plus the deployment tag. Langfuse's own
  `events_traces` view is withheld from the public v2 API, so the same aggregate
  is requested through `view:"observations"`. A failed aggregate fails the
  request, because zero is indistinguishable from a free trace. The root span
  counts toward the total, unlike Langfuse's view, so a single-span trace is not
  reported as free. `TraceDetailPanel` takes cost from the detail response, since
  `??` treats the list's zero as present.
- **#2031** (`langfuse-v4-opt-in`): `LANGFUSE_USE_V4_API` flips from opt-out to
  opt-in. An environment writing in `legacy` mode has no populated v4 tables and
  the v4 endpoints answer a miss with `200` and an empty list, so the opt-out
  default silently emptied any environment that had not cut over.
