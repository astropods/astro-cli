# Release — 2026-04-29.1

## CLI Command Tree Redesign

`ast` has been restructured into nested command groups. `ast agent` covers running deployments (`list`, `get`, `pause`, `resume`, `delete`, `restart`, `redeploy`, `history`, `logs --tail`). `ast blueprint` covers the build/push/deploy lifecycle (`build`, `push`, `validate`, `deploy`, `get`). `ast spec` covers spec authoring (`validate`, `explain`, `repair`). New `ast settings` group manages telemetry and shell completions. `ast secrets` and `ast account` round out the surface. `ast dev` is now `ast project` (old name aliased).

`blueprint push` builds by default (use `--no-build` to skip). The agent name is positional and optional on `build`/`push`, falling back to the spec. New `--var KEY=VALUE` / `--vars-file` flags accept the same forms across `deploy` and `redeploy`, including `KEY=@SECRET` references and `KEY=@@` self-references. Several flags are gone — among them `--skip-build`, `--skip-push`, `--skip-register`, `--no-auth`, `--server`, `--registry`, `--platform`, and the old `configure set/unset` subcommands (now `--var`/`--rm-var` on `configure`).

`secret create` and `update` accept `--description/-d` and prompt for one interactively. `secret create` and `blueprint create` validate names client-side. `bp get` gains `--card` (rendered markdown) and `--template` (variable list, required first). The CLI no longer requires Docker on `$PATH`; missing-vs-not-running surfaces a clearer message. Org-scoped names like `@org/foo` no longer leak into Docker tags.

## Per-Deployment Authorization

Deployments can now declare who is allowed to use each interface in the spec. The `interfaces.auth.{web,slack}.grants[]` block accepts three subject types: a specific account, a specific user (web only), or `anyone: true`. The messaging container enforces these grants on every request — fast-path for `anyone` via signed token claim, server lookup otherwise. Deployments with no grants fall back to owner-account access for backward compatibility.

## Knowledge Store Bindings

Agents can bind knowledge entries directly to managed knowledge stores by ARN at deploy time, instead of supplying credentials. The deploy form has a per-entry binding picker filtered to compatible providers. The server validates ownership and provider match, resolves credentials from the store, and skips creating a per-agent service/StatefulSet/secret for bound entries. Deleting a store with active bindings is blocked.

## Blueprint Detail Redesign

The blueprint detail page has been visually overhauled — avatar-tinted radial gradients, subtle SVG grid backgrounds, holographic deploy CTA with cursor tracking, and tighter `4px` panel radii. Avatar color extraction was rewritten end-to-end: blueprints now generate four palette targets (vibrant / light vibrant / dark vibrant / muted) from the avatar, used consistently across cards and the detail view. Existing blueprints get re-extracted automatically on the next read.

## Blueprint Authors

The blueprint detail sidebar now shows real publishers, sourced from the audit log of past `agent.register` actions ordered by first push. Names resolve through the identity provider with the account handle as fallback. The previous best-effort author lookup from `AGENT.md` has been retired.

## Blueprint Link Previews

Public blueprints now unfurl as 630×630 OG images on Slack/X/LinkedIn. The image renders the avatar, blueprint grid, teal glow, and Astro AI wordmark. Private and draft blueprints emit no `og:image`. Image rendering moved from Go to a TypeScript-side rasterizer with bundled fonts, served from the web app directly.

## GitHub Monorepo Support

A single repo can now back multiple blueprints at different subpaths. The repo picker accepts a free-text subpath that is validated server-side against the GitHub Contents API. A push to the repo fans out to every linked subpath connection across accounts; webhooks are deduplicated globally, so a repo only ever has one webhook regardless of how many accounts or subpaths use it. Repo links in the sidebar deep-link to the subpath.

## Theme & Dark Mode

A new `card` semantic token sits between `surface` and `popover`, with a matching `<Card>` primitive. The teal palette has been desaturated and shifted toward slate for a calmer dark-mode feel. Page backgrounds, OrgSwitcher, MetricCard, and FilterInput now have proper dark-mode treatments. Theme and experiment toggles propagate live across the header without a refresh.

## Logged-Out Nav

The signed-out top nav has been reorganized into a secondary-links zone and an auth zone. The CTA reads "Get started"; "Log in" is a small ghost button. Mobile collapses gracefully — secondary links visible above 700px, hamburger hidden when logged out, Log in folds into the sheet below 380px.

## Scope Switcher

The org/account switcher has been rebuilt as a form-field dropdown with avatar and moved to the right-side action slot on Blueprints, Agents, and Knowledge Stores. The Explore telescope icon rotates on hover.

## Admin TUI

The admin TUI (`astro-queen`) gains owner-email columns/cards on deployments, batched via the identity provider. New Pause / Unpause controls (and Bulk Pause / Wake Up) sit alongside the existing lifecycle actions. The Agents page is renamed Blueprints throughout, matching the public surface.

## Fixes

- Deployments in `pending` or `provisioning` can now be deleted; previously only terminal states were allowed
- A subtle bug caused secrets created or updated when KMS was disabled to be base64 plaintext rather than raw plaintext — fixed; affected secrets need to be re-saved
- Blueprints/deployments created before color extraction landed now generate themes on read
- Cross-account Configure prefill no longer 404s when the source account differs from the active account
- Cross-account upgrade prompts and "new build available" banners only show builds from origins the viewer can actually deploy
- The new-blueprint wizard no longer flashes a blank source card when returning from GitHub OAuth
- The Blueprints page no longer flashes its empty state on refresh — replaced with shaped skeletons backed by an SSR loader
- Deploy template scaffolds (`mastra` and `langchain`) now include the required `meta` block and validate cleanly
- The Layout's red inline error banner has been removed in favor of future toast handling
- Slack-enabled deploys via the CLI-direct or partial-grants paths no longer ship empty authorization claims

## Migration

| Change | Action |
|---|---|
| Token env var renamed | Update agents reading `ASTRO_DEPLOY_TOKEN` to read `ASTRO_AUTHZ_TOKEN` |
| Agent URL/host env vars renamed | Update agents reading `AGENT_URL`/`AGENT_HOST` to read `ASTRO_AGENT_URL`/`ASTRO_AGENT_HOST` |
| `DEPLOY_TOKEN_SECRET` required | Operators must set this in production |
| `meta` block in spec | Optional; `visibility` is no longer read from spec — pass `--public`/`--private` to `ast push` |
| GitHub webhooks | Webhook ownership moved to a global table — internal users may need to disconnect and reconnect once |
| `deployments.source_account_id` schema | Apply schema migration before deploying the new server image |
| KMS-disabled secrets | Affected variables need to be re-saved to clear stale base64 plaintext values |
