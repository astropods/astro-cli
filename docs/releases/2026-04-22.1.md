# Release — 2026-04-22.1

## Server-Driven Deploy Form

The deploy form no longer assembles its own configuration client-side. A new interactive POST template endpoint lets the server own template shaping — adapter selection, variable filling, schedule validation, and auth configuration all happen server-side. The client sends the current form state and receives a ready-to-render spec back, eliminating an entire class of drift bugs between what the UI shows and what the server expects. The old GET template endpoint and its client-side shaping code have been removed.

## Navigation Redesign

The global navigation has been reworked. A compact scope switcher replaces the old org dropdown, links are centered with count tags, and the Organizations section has been removed from the profile dropdown. The `/dashboard` route is now `/agents`. A new shared `ActiveAccountProvider` eliminates per-page scope switchers. On mobile, the header collapses gracefully — Explore becomes an icon button, Docs/Blog/Feedback fold into the hamburger menu, and blueprint breadcrumbs shrink to avatar + username. A dedicated `/explore` route replaces the in-page community section on Blueprints.

## Knowledge Store Detail Overhaul

The knowledge store detail page has had a full design pass. Metric cards now show sparklines, value suffixes, and descriptions. The configure form aligns with the deploy form pattern (variables & secrets empty state, tokenized typography). Provider selection cards have been polished with updated brand icons (Qdrant, Neo4j, MySQL). The post-create flow now includes celebratory confetti on success and an information-dense PrivateLink pending-acceptance screen with a vertical step card layout. K8s events display inline during provisioning with type-appropriate icons and humanized messages.

## Build Log Viewer

GitHub builds now have a proper log viewer. A new `BuildLogViewer` component shows per-section accordions with status icons, durations, and pending states. Log lines use the shared LogViewer styling (timestamps, level coloring). A header bar shows the commit-to-build breadcrumb linking the GitHub commit to the Astro build.

## Log Viewer Improvements

Three additions to the log viewer: timezone support (user-configurable, stored per-user in localStorage, applied server-side), search highlighting that shows matches inline instead of filtering rows away, and a refresh button for re-fetching the current time interval. The viewer is now virtualized for scalable rendering at high log volumes.

## Identity Generation Rewrite

Avatar generation has moved from a TypeScript client-side package to a Go implementation served from S3. Avatars are generated at blueprint creation, cached, and served with cache-busting on update. The TypeScript identitygen package has been deleted.

## CLI Changes

- `ast push` now accepts `--public` / `--private` flags to control blueprint visibility; the `visibility` field in `astropods.yml` is no longer read
- `ast push` validates the spec strictly (full semantic parser + JSON-schema) before any Docker build or registry upload
- New `ast secrets` command group for managing account-scoped secrets and variables
- `ASTRO_NO_KEYRING` env var removed — keyring is now skipped automatically during testing
- `ast configure` persistence and `ast dev` scoped-name cleanup regressions fixed

## Auth & Permissions

- Org admins can no longer remove or demote owners — the server now enforces this boundary
- Role badges (owner/admin/member) restored on the Organizations settings page
- Loader-based redirects replace `<Navigate>` components, fixing an SSR warning on initial render

## Fixes

- Environment variables no longer shuffle on every poll — sorted alphabetically
- Deployment detail container names are always populated from the K8s manifest
- Vault references now load correctly in Slack credential fields
- Blueprint names that were ever public or deployed are now reserved to prevent reuse conflicts
- GitHub repo dropdown no longer appears empty after the Search API migration
- Account name format is validated on creation
- Postgres knowledge stores get writable socket dirs and generated credentials
- Postgres health check targets the correct database
