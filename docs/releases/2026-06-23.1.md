# 2026-06-23.1

## Chat: switch agents and keep your history

The web chat experience is rebuilt around a single agent switcher and durable conversation history.

- The thread header now carries the same agent dropdown used on the agent detail page, so you can jump between any chat-eligible agent you can reach — across every account you belong to — without an account switcher or a left rail.
- A **History** dropdown lists your past conversations, each with a live "reply in progress" dot, plus a one-click new chat.
- Conversations now survive navigation, reload, and switching devices. Message history is restored from your traces when available, with a durable fallback so nothing is lost mid-reply.
- Switching conversations mid-stream, reopening a tab during an in-flight reply, and rapid sends no longer produce duplicate messages, stuck spinners, or crashes.

## Creating a blueprint is smoother end to end

A pass across the New Agent wizard removes friction at every step of the GitHub setup flow.

- If your account is already connected to GitHub, the redundant "Connect GitHub" step is skipped and your repositories load directly.
- The repository picker opens when you click anywhere on the control, not just the chevron, and org-owned repos now show their owner (`owner/repo`) so they're distinguishable from personal repos.
- The branch selector lists the repository's actual branches instead of a hardcoded `main`/`master`.
- The setup screen scrolls when its content is taller than the viewport, and the wizard's steps no longer render blank or misaligned after going back or reloading.
- A blank blueprint name can no longer slip through; invalid input now reports an inline reason on submit.
- When you hit an agents quota, the message links straight to the correct account's **Settings → Usage** and offers a quota-increase request.

## Explore: search and sort

The Explore community blueprints page gains a search box and a sort control (Most deploys, Most hearted, Last updated, Name A–Z) so you can browse the catalog by relevance and activity.

## Upgrade banner tells you what's new

The "New build available" nudge on the agent detail page now shows the upgrade target's commit message and short SHA, linked straight to the commit on GitHub, instead of an opaque build-id transition. Builds pushed directly from the CLI (no commit) keep the previous display.

## Settings polish

- **Connectors** is redesigned as a clean inline-row list. GitHub and Slack each get a single row with a kebab menu for actions (Reauthorize / Disconnect), and Slack workspaces can be added or removed individually.
- The Account, Organizations, and Experiments tabs share a unified header treatment; organization rows are now fully clickable cards.

## Insights: faster and fresher

- Tables open with 25 rows instead of 5, so the first screen matches what operators typically scan. "Show more" continues to reveal additional rows in bounded steps.
- Slack profile details — names, avatars, and workspace icons — now refresh as soon as they change rather than lagging behind by up to several hours. Linking a Slack account to Astro is reflected immediately.
- The page loads through a single consolidated request, keeping search, sort, and pagination snappy on large accounts.
- The traces table and trace detail panel get a visual polish pass: consistent identity sizing, clearer section headers, more legible trace IDs, and dark-mode-correct error coloring.

## Monitoring and adapter docs

- A new **Monitor your agents** section in the public docs explains automatic monitoring and includes per-framework setup guides for Mastra and the Claude Agent SDK.
- A new guide documents the **Vercel AI SDK** adapter (`@astropods/adapter-ai-sdk`) for telemetry and messaging.
- New guides cover building frontend agents and consuming the messaging authorization endpoint.

## Fixes

- Hard-refreshing the Insights page on large organizations no longer hangs on a blank loading shell — the page now renders reliably on refresh, matching navigation.
- Private knowledge store provisioning no longer fails when an endpoint service isn't available in every availability zone; endpoints are now placed only in supported zones.
- Restored the shared Button and Tooltip styling that a previous change had overwritten app-wide.
- Dark-mode accessibility fixes for the deploy form link color and the unchecked interface icon background.

## Migration

| Change | Action |
|--------|--------|
| Chat history schema | Apply `sql/astro-server/schema.sql` (Atlas) before deploying. Deploy astro-server before or with astro-client. |
| PrivateLink AZ selection | Requires `ec2:DescribeVpcEndpointServices` and `ec2:DescribeSubnets` on the astro-server IRSA role (added in the infra repo). |
| In-client chat networking | Deploy the astro-infra change so astro-server receives `CP_SUBNET_CIDRS`, then redeploy agents so tenant namespaces pick up the `allow-apiserver-proxy` policy. |

No action required for any other change.
