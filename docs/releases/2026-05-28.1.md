# Release 2026-05-28.1

## Sizing knobs and persistent volumes for agents

Deployers can now size an agent and attach a persistent disk to it directly from the deploy form. The form has a new **Volume** section next to the existing top-level choices (interfaces, knowledge, credentials), and a collapsible **Advanced** panel housing CPU, memory, and (when a volume is enabled) storage tier sliders. A live cost estimate broken down by CPU, RAM, and storage is visible on the Advanced header, so the impact of each adjustment is visible without expanding the panel.

- CPU ladder: `25m / 50m / 100m / 250m / 500m / 1`, default `100m`.
- Memory ladder: `256Mi / 512Mi / 1Gi / 2Gi / 4Gi`, default `1Gi`.
- Storage ladder: `5 / 10 / 20 / 30 / 50 Gi`, default `10Gi`.

Volumes are mounted at a user-picked path; agent data persists across redeploys for as long as the volume stays on. Toggling the volume off on a redeploy fully releases the disk (no orphan billing). The storage size is locked once a volume is live, because the underlying disk cannot be resized in place — to change it, turn the volume off, redeploy, then re-enable at a fresh size.

The deployment details Metrics tab renders the pod's CPU and memory limits as dashed reference lines, with the Y-axis pinned to the limit so headroom is visible at a glance.

## Per-cluster ingress, certificates, and knowledge domain

Operators running additional clusters can now declare each cluster's own ingress domain, ACM certificate ARN, ALB group names (agent + ingestion), and public knowledge domain at registration time. Until this release, deploys targeting non-primary clusters silently inherited primary-cluster values, which produced ALBs in the wrong account, certificates that didn't match the host, and knowledge stores published into the wrong zone.

The primary cluster continues to read its values from the process env vars it always did. Non-primary clusters have **no env-var fallback** — registration and updates reject empty values, and deploys validate again before applying, so misconfiguration fails fast with a clear error.

## Operator visibility into cluster placement

Operators can now see when an account's home cluster and a deployment's actual routed cluster diverge — for example, an account pinned to EU with a deployment still landing on primary. The Queen deployments list gains a Cluster column and a mismatch badge (with tooltip), and the deployment detail view shows side-by-side account/deployment cluster cards that highlight mismatches in amber. The detail view also surfaces the cluster the K8s API call is actually targeting (which may differ from the row's cluster when overrides are in play).

A pair of admin RPCs lets an operator manually clear the new agents-page caches without waiting for the safety TTL — per-account or global. The global variant requires a two-click arm/confirm and is audit-logged.

## Agents page rebuilt: new card, sub-second loads

The Agents page has been rebuilt around a new card design and a read-through cache so the grid loads in well under a second.

- **Card**: avatar-tinted gradient + seeded starfield + nebula tint, with a vertically stacked layout (status pills + per-deployment request/token sparkline + action row). The action row is pinned at the bottom of every card so it stays aligned across the row even when peers carry status pills.
- **Speed**: per-card Langfuse and K8s fan-out is gone from the request path. Both per-deployment activity sparklines and the deployment list itself are read-through caches that a background worker refreshes; cache busts fire from every write that affects the data (deploy, undeploy, rollback, reconcile, rename, avatar change, publish), so the "Update available" pill appears immediately rather than waiting on TTL.
- **Toolbar**: search is now left-aligned, filters right-aligned. The all-time **Total Tokens / Total Requests / Total Compute** row at the top of the page is gone.
- **Polish**: the **Launch** button now stays visible whenever a messaging URL exists (the URL is final the moment the deploy applies, even before the load balancer is fully provisioned). The red **Error** pill is now only shown when the deployment is actually in an error state, not just when a stale `error_message` is on the row.

## Deploy form respects each agent's interfaces

Agents that ship their own web frontend and don't run the messaging sidecar no longer see the Slack/Web adapter picker in the deploy form. For those agents, the picker had nothing meaningful to offer — selecting an adapter was a no-op. The form now reads what the agent declares and only renders the picker (and its validation) when messaging is actually supported.

## Inline secrets preserved across configure / redeploy

Inline deployment secrets (typed directly at deploy time, as opposed to vault references) now round-trip through configure and redeploy. The configure form shows a `••••••••` placeholder when a value is stored, clicking enters edit mode, and a redeploy that omits an unchanged secret carries the stored value forward instead of failing validation or wiping the credential.

## Public URL readiness on the API and CLI

Deployment endpoints now expose a `ready` flag and a user-facing `message` per endpoint. The web Launch button uses this to disable itself with a clear tooltip while the load balancer is still being provisioned. `ast deploy --wait` polls until the messaging URL is ready, and `ast agent get` prints the URL with readiness alongside it.

## Faster Insights page

The Insights page now fetches all-time data **once per session** and slices client-side. Range chips (7D / 14D / 30D / All-time) and filter chips become 0ms in-memory recomputations instead of fresh server queries — no more lag with the old number under the new label until a request returns.

Other Insights changes:

- **Two charts side-by-side**: Agent Spend (per-agent breakdown) on the left, Total Spend (dual-line: total $ and active user count) on the right.
- **Toggle independence**: the date-range chip drives the charts only; the By-Agent / By-User toggle drives the table only. Flipping the view no longer refetches or remounts the upper page.
- **Users column** on the agents-view Top Spenders table, with avatar chips.
- **Background refresh**: the page now refetches every 5 minutes so it stays fresh for users who leave the dashboard open.
- **Chart axis**: bar charts now span the full requested window rather than starting on the first day with data, so a quiet first week looks quiet instead of being hidden.
- **Stat cards**: change % is now inline with the value (constant card height across ranges including all-time); sparklines and the `— —` placeholder are gone.
- **Bucket rename**: the "Unauthorized" user bucket is now called "Unidentified."
- Top Spenders headers show entity counts (`Agent 12`, `User 47`).

## Profile page polish

Cleaner shell background (`bg-background`) across all routes, with stronger dark-mode grid contrast. Single-tab profiles (the common public case) now render the section title as a plain heading instead of a lonely underlined tab. Tab grids respond to the available content width via container queries, so they reflow when the profile sidebar is open. Empty-state tab toolbars are hidden until there's something to search or sort.

## GitHub reauthorize works

The **Reauthorize** button in Settings → Connectors no longer no-ops. The connector card also surfaces a "Request access on GitHub" link in both the zero-orgs and has-orgs states, since GitHub's OAuth re-auth does not re-show the org selection screen for already-authorized apps — org access must be managed in GitHub settings directly.

## CLI: uniform cancel UX

Every interactive prompt and TUI in `astro-cli` now accepts `esc` (and `ctrl+c`) to cancel, advertises that key in a footer line styled the same way across surfaces, and exits 0 with a dim `Cancelled.` line on abort. Three forms (`secrets create`, `secrets update`, the username claim in `login`) that previously exited non-zero on Ctrl+C now exit cleanly.

The CLI gets a bundle of related fixes:

- **Error messages reference the actual binary name.** When the binary is invoked as `ast-dev`, `ast-preview`, etc., user-facing suggestions like "Run 'ast login'" now correctly suggest `ast-dev login`.
- **`ast project start --local` cleans up properly on Ctrl+C.** Previously `bun --watch` workers and any agent-spawned grandchildren were left running as orphans holding ports, file watches, and credentials. The agent process tree is now killed as a group on shutdown.
- **`ast push` and `ast secrets` fetch credentials at use time, not command start**, and recover from a mid-flight 401 with a single refresh + retry — no more "token expired" failures during long Docker builds.
- **`ast push` visibility prompt moved before the build step.** Declining the visibility change no longer wastes minutes of build work.
- **`ast create` no longer prints a Claude prompt with an empty goal** when the form is cancelled.

## Configure page: detects resource-config changes

Editing only the advanced provisioning fields (CPU, memory, volume mount, storage size) on the deploy configure page now surfaces the **Save & Redeploy** action bar like every other redeploy-triggering field. Previously the form sent the new values on an unrelated save but never signaled that a redeploy was needed.

## Fixes

- Deploy form's knowledge binding rows and persistent-volume picker no longer show a light icon backing on a dark surface in dark mode.
- Insights table view toggle no longer refetches the upper page; chart subtree stays mounted across toggles.
- Auto-fill newly created variables in the deploy form so users don't have to re-type the value they just created.

## Migration

| Change | Action |
|---|---|
| Signed templates are now mandatory on `POST /deploy` | The bundled CLI and web client already do this. External clients must call `POST /deployment-template` with `finalize: true` and forward `X-Template-Signature`. Unsigned deploys are rejected. |
| `AstroDeploymentSpec.editable` / `TemplateResponse.editable` removed | Read resolved values directly off `template.agent` / `provisioning.agent`. |
| Per-cluster ingress fields on `clusters` | Apply the schema migration (no backfill). For each additional cluster, call `UpdateCluster` (or use Queen) to set its ingress domain, ACM ARN, ALB group names, and knowledge domain. Until done, deploys to that cluster fail fast with a clear error. The primary cluster needs nothing. |

## Provisioning knobs + agent volumes (#1142)

- `POST /api/v1/agents/:account/:name/deployment-template` accepts a `provisioning.agent.{compute,volume}` block. Server applies on top of `StandardResources` + `DefaultStorageConfig()` per field. `ComponentCompute` exposes only `cpu`/`memory`; server sets requests==limits → Guaranteed QoS.
- `TemplateResponse.provisioning` echoes resolved values.
- `DeploymentAgent` gains `volume` + `storage`. Non-empty volume switches the agent from Deployment to StatefulSet via `applyAgentWorkload`. StatefulSet sets `PVCRetentionPolicy{WhenDeleted:Delete, WhenScaled:Delete}` — without this, toggling volume off on redeploy would orphan the PVC (stale cleanup deletes the STS by build label but never touches PVCs). Knowledge stores keep their existing `Retain/Delete` policy.
- `StandardResources` now `100m/1Gi` (was 8Gi default-anchor). `MessagingResources` (`100m/256Mi`) and `CollectorResources` (`50m/128Mi`) follow the same request==limit pattern so the pod stays Guaranteed.
- `Editable` / `EnforceEditable` removed. Signature verification (HMAC-SHA256 over canonical spec, target fields excluded) is now the only integrity check. `/deploy/validate` skips the signature check.
- `GET /deployments/:id/pods/:pod/metrics` returns `cpu_limit` (vCPU) and `memory_limit` (bytes) summed across regular containers + Always-restart init sidecars.
