# Release 2026-06-04.1

## Agents page: per-deployment Insights, tombstones, and clickable cards

Insights now treats each deployment as its own row instead of rolling multi-region deployments under one agent name. Every deployment gets its own table row, its own line on the Agent spend chart, and a click that deep-links straight into that deployment's Monitor tab. Chart legends are clickable to toggle series visibility (helpful when one outlier deployment is dominating the y-axis), and the last visible series is locked on so the chart can't be accidentally emptied.

A new **Show deleted** toggle on the Agents view brings tombstoned deployments back into the picture: their historical spend rolls into the table, charts, and headline numbers. Live rows get a small green dot trailing the name; deleted rows get a red dot whose hover reveals the deletion date and a muted, non-interactive presentation that won't 404 you onto a torn-down deployment. The People-tab's "Agents Used" chip column gets the same `(deleted)` treatment for archived-only attribution.

Other Insights and chart polish:

- **Filter input** — chip-based multi-select is gone; a single search box filters by agent name (Agents view) or display name / username / Slack id (People view). Switching views clears the query.
- **View toggle** — redesigned as **People (N) / Agents (N)** pills with icons + tabular-num counts, matching the canonical toggle chrome used elsewhere.
- **Chart titles** — *Agent Spend* → **Agent spend over time**, *Total Spend* → **People spend over time**; the users line is recolored from orange to indigo so warning/error/success colors stay reserved for status.
- **% Total** column on Top Spenders, denominator anchored to the unfiltered total so percentages stay stable while you search.
- **System spend** replaces "Infrastructure" for the unattributed bucket; **Person** column replaces "User"; clickable overflow `+N` popovers replace the old aria-only / hover treatment; Person rows now link to the user's profile.
- **Empty state** — the page no longer collapses to a centered "no insights" CTA; stat cards render at 0 with chart placeholders so the layout stays stable on a quiet account.
- **All-time toggle retired**; **90D** added. The Agents and People tables continue to show lifetime totals.

Agent cards on `/agents` are now click-to-open: clicking anywhere on a card opens that deployment's Monitor tab, while the Manage button stays on the default detail panel. The kebab menu loses the **Delete agent** entry (real permission enforcement lands later with fine-grained access control; until then, deletion stays on the agent detail and configure Danger Zone). The status filter is gone from the toolbar — the redesigned card never surfaced live status as a primary concept and the filter vocabulary was misleading.

The **View badge** action is restored on the kebab menu and the agent identity dropdown. The badge modal itself swaps the two bare Download buttons for a single **Share badge** dropdown (Share on X, Share on LinkedIn, Download PNG, Download SVG) — matching the post-deploy reveal.

## Local-mode deployments work end-to-end

Local deployments (`K8sClientMode=local`, Docker Desktop / k3d) now ship a working Launch URL out of the box: the messaging Service is promoted to a NodePort with a Kubernetes-auto-allocated port, the deployment endpoint surfaces a `http://localhost:<port>` URL, and the Launch button picks it up like any remote deploy. Multiple local deployments can run side-by-side — each gets its own port.

Authentication works locally too. Messaging now treats every request as the account owner (resolved at deploy time), mimicking the prod ALB → OIDC header flow without needing an actual ingress in the path. The pod-reachable authz callback URL rewrites `localhost`/`127.0.0.1` to `host.docker.internal` before signing so the messaging pod can reach back into astro-server; the Vite dev server is configured to accept that Host header so its `/api` proxy forwards through.

## Slack user attribution on traces and Insights

Slack messages now flow with the right user identity through the trace pipeline. Members who linked their Slack identity show up in Insights under their named-member row instead of as a raw `U07…` id, and their pre-link Slack spend and post-link Astro spend collapse into one row. Slack users who haven't linked still surface — each gets their own row in People view with a clickable deep link that opens their Slack profile in the workspace, instead of disappearing into a single aggregated bucket.

A one-shot historical backfill runs automatically on first deploy of the release so existing pre-link Slack traffic gains its deep link without requiring users to send new messages first. The "Unidentified" bucket now correctly describes what actually lands there post-release: arbitrary non-WorkOS, non-Slack trace ids from custom integrations or direct SDK calls.

## Deployment status, unified

The agent status surfaces now agree with each other. The top-right toggle and the deployment-history tiles use one vocabulary ("Deploying", not "Resuming") for the same transition, and use the same warning palette while a deploy is in flight. Tile colors moved to semantic tokens so the **Deploying** badge is readable in light mode (it was effectively yellow-on-white before). Pod tiles no longer flicker out and back in on pause / resume — the spec workload list is the stable source of truth for which tiles to render, and only their state changes.

Behind the scenes the deployment detail endpoint was split into record / runtime / status surfaces with disjoint responsibilities — see the appendix. The visible effect is that brief cluster blips no longer drag the badge into "Deploying", mutations consistently invalidate every relevant cache, and the toggle tooltip now displays a server-derived sentence (e.g. "1 of 3 replicas ready") instead of guessing.

## Blueprint sidebar polish

The "Authors" section is renamed to **Contributors** — the section credits commit authors and maintainers, not just the original author. The Repository row is split into two links: the top row goes to the repo URL, and (when the blueprint specifies a directory) a second row links into that subdirectory on the host provider (GitHub, GitLab, Bitbucket). The blueprint draft → published transition no longer fires a full-screen "Blueprint is live" overlay — the wizard arrives directly on the blueprint detail page.

The `/blueprints` page drops its "Per page" toggle and the cookie/localStorage preference behind it; the page always loads 50 per page, and pagination only appears once total exceeds that. Page changes also smooth-scroll the viewport back to the top.

The InviteInput member combobox shows avatars and display names in both pills and dropdown rows (matching the existing MemberPicker treatment) instead of the bare handle, and swaps the legacy teal palette for semantic tokens.

## CLI: `ast agent trace`, `ast agent logs` for any workload, target by flag

`ast agent trace` is new. It mirrors the Monitor tab's two endpoints and adds a third mode for the agents-page card:

- list traces (default) — paginated by `--limit` / `--offset`, optionally bounded by `--start` / `--end` (RFC3339);
- detail (`--trace-id`) — full input/output, observations sorted by start time, scores;
- activity summary (`--summary`) — total traces, last active, and a Unicode-block sparkline of the per-day request and token series (same source as the `/agents` card sparkline);
- `--json` on any mode emits the raw server response for piping into `jq`.

A decode failure on traces with object-shaped `input`/`output` is fixed in the same change.

`ast agent logs` is unlocked for non-agent workloads. The new `--workload` flag takes `workload[/container]` and resolves by exact name, entry-name suffix (`vectors` → `my-agent-knowledge-vectors`), or component label (`agent`, `messaging`, `collector`). The old `app` / `messaging` container whitelist is gone — the CLI delegates container validation to the server, which already cross-checks against the pod's actual container list. `ast agent get` now prints each workload's Kubernetes name next to its component so you know what to pass to `--workload`.

All `ast agent` subcommands now require `--name` or `--id` to identify their target (mutually exclusive, one required). Positional targets, argv-joining for multi-word names, and the ID auto-detect path are gone — quote multi-word display names in the shell. `--confirm` on delete still accepts either a name or an id.

`ast login` now preserves the active org across re-authentication. If you were working in an org when your token expired, you land back on that org instead of being bounced to personal. `ast login --account <name>` continues to override; if your prior account has been removed, login falls back to personal and prints a one-line note.

## Other CLI and operator fixes

- **Log viewer time range fixed.** The agent detail logs viewer was returning the *oldest* 200 lines from a window (so widening the range made the newest log appear older). The query now sets `Direction: backward`, and scrolling up at the top of the log viewer fetches another 500 older lines within the same window via infinite scroll. Scroll position is preserved as new entries prepend.
- **Trace detail timeouts** on agents with large tool outputs (GitHub PR diffs, Confluence pages, project reports) are fixed. The trace tree renders immediately from a structural-only query; selecting a node fetches that observation's full input/output on demand.
- **Agents grid Launch button** is gated on `status === "Running"`; it stays hidden when a deployment is stopped, deploying, or in error.
- **Agents grid `Error` badge** is now derived from the deployment's actual status (not just the presence of an `error_message`), so paused / stopped deployments with stale messages no longer turn red. The same handler also stops storing informational messages (admin stop reasons, scale events) in the error field.
- **Quick switcher staleness after delete** — deleted agents lingered in the agent-detail quick switcher for up to a minute after the agents page had dropped them. Fixed.
- **Account renames now sync the billing display name** so renamed orgs no longer keep the old label in operator views.
- **Top progress bar on org switch** is reliable on warm pages — switching from a heavy `/agents` page no longer makes the bar appear late or skip the dropdown close animation.

## Documentation: agent instrumentation guide

`ast docs agent` gains a focused **Instrumentation** section between Environment Variables and Project Structure. It calls out the right OTel library per stack (Mastra one-line, Traceloop for LangChain / LangGraph, `@arizeai/openinference-instrumentation-claude-agent-sdk` with the `manuallyInstrument` constraint for the Claude Agent SDK, OpenInference / Traceloop for raw Anthropic / OpenAI) and names the three env vars the platform injects automatically. Off-the-shelf libraries are framed as the recommended path; manual GenAI/OpenInference span emission is the documented fallback.

## Fixes

- **AGENT.md frontmatter** is now parsed leniently — a malformed YAML token, an oversized tags list, or the wrong type for one field no longer drops the entire card. Whatever parses is kept, the rest is dropped silently with a warning printed by `ast push` / `ast dev`.
- **Vault secret edit dialog** no longer shows a reveal toggle on an empty field (secrets are write-only on the server, so the toggle could never reveal the stored value). Description-only edits are now allowed without re-entering the secret value.
- **Pod metrics and logs on additional clusters** (e.g. EU) now scope correctly — previously every Prometheus / Loki query was hardcoded to the primary cluster's name, so non-primary deployments showed empty charts and missing logs.
- **Agents grid messaging URL** is now populated in the cached list payload, restoring the Launch button (the redesigned card was reading the right field; the cached payload just wasn't filling it).
- **Network flows table** on the Monitor page is rebuilt on the shared Table primitive so it inherits the same chrome as siblings (top spenders, audit log, knowledge stores). The "Destinations / N peers" strip moves inline next to the column header.
- **Insights & summary 5xx storms during Langfuse outages** — the three Insights endpoints now degrade gracefully, returning `200 OK` with `metrics_unavailable: true` and a banner instead of erroring; a 6h Redis cache pre-warmed by a periodic worker means cached values survive multi-hour upstream outages. ClickHouse cardinality on the People-tab primary query was also cut ~24× by switching from hour to day granularity, fixing the underlying timeouts that were causing $0 / 0-request rows for active users.
- **Insights blueprint wizard** — creating a blueprint scoped to an organization now scopes the JWT to that org at publish time, fixing the "session is not scoped to this organization" 403.
- **Configure Volume picker and Advanced sizing panel** got a polish pass — the Volume row uses the shared Switch primitive with semantic theming, dark-mode invisibility on selected states is gone, and the Advanced panel's cost anchor stays in one place across collapse states.
- **Usage page** groups meters into Agents / Knowledge / Account sections; the compute-unit explanation moves into an inline tooltip; quota-request status badges use the canonical `StatusBadge`.
- **Smoke teardown** alignment with the new `ast agent delete --name <name>` surface.
- **Local-dev cleanup** — `scripts/local-dev.sh` propagates signals through the whole process group on Ctrl+C, so the next run isn't blocked by port-in-use errors; the agent port-forward helper now defaults to `:18090` (was `:8090`, colliding with Traefik).
- **Collector self-spans** — the OTel collector now drops spans that describe the act of exporting telemetry to itself (HTTP `/v1/traces` etc., gRPC `opentelemetry.proto.collector.*`), so request counts and trace volumes in Insights / Langfuse are no longer inflated by the export loop on busy agents.

## Local-mode messaging

- Messaging Service promoted from `ClusterIP` → `NodePort` in local mode (`localMode && webEnabled`). NodePort auto-allocated by kube-proxy (no pinned port; concurrent local deploys would collide otherwise). Vite dev server allows `host.docker.internal` Host so `/api` proxy forwards. Browser-facing redirects continue to use unrewritten URL.

## Trace detail lazy-load (#1227)

- `GetTrace` fires two Langfuse requests concurrently:
