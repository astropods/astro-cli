# Release — 2026-04-10.2

## Create a Blueprint

You can now create a new blueprint directly from the UI. A short setup wizard walks you through picking a name, visibility, categories, and an avatar. After creation, the blueprint opens in a draft state with a "Finish setting up" panel that shows copy-paste commands for Terminal, Claude Code, and Cursor to scaffold and push your agent. The draft banner clears automatically once your first `ast push` lands.

Blueprint cards in the browse view and dashboard show a yellow "Finish setting up" badge while in draft state.

## Organization Settings

The organization settings area is now fully functional.

**Members:** The members page shows active members and pending invitations in one table. Invitations appear immediately when sent. Removing a pending member revokes the invitation so the link can't be re-accepted.

**Roles:** Admins can invite members, edit the org profile, change the username, and delete the org. Non-admins see these controls disabled with a tooltip explaining why. Leaving the org is available to everyone.

## Logs

Opening the Logs tab now loads the current deployment's containers automatically — no need to manually select one first. Each container opens as a closable tab; tabs stay open when you switch to other sections and come back.

## Fixes

- Avatar uploads now preview immediately before saving; SVG files are rejected
- Org avatars appear correctly in the organization listing
- Organizations no longer show up in your account list before you've accepted an invitation
- Public pages are accessible without logging in

## Appendix — Internal Details

**Commit range:** `484c9c57..c2e4bf40`

**Blueprint creation**
- Draft state derived client-side from `versions.length === 0` — no separate DB flag
- Detail page polls for first version after creation; transitions out of draft automatically
- `AvatarPicker` replaced with `AvatarUploadDialog` — staged blob pattern: preview is immediate, upload fires on save
- SVG uploads rejected at the server handler level (XSS prevention)
- SSR hydration race fixed in avatar fallback: `useSyncExternalStore` now provides a `getServerSnapshot`; a post-mount `useEffect` catches 404s that fired before React hydrated

**Org member management**
- `GET /accounts/:account/members?include_pending=true` returns WorkOS memberships not yet synced to the local DB — only the settings page uses this param
- `useCreateInvitations` inserts optimistic pending rows into the members cache on send
- `Sync.RemoveMember` extended to handle members with no local DB row by falling back to WorkOS lookup; also revokes outstanding WorkOS invitations on removal
- Event consumer now skips non-active membership events — fixes orgs appearing in account list before invitation is accepted

**Logs**
- Log viewer extracted to a standalone `LogViewer` component (no deployment-specific logic)
- Logs tab removed from the Deployments accordion; per-container tabs persist across tab navigation within the same deployment

**Public access**
- `WaitlistGuard` removed — was redirecting unauthenticated users to an external waitlist URL
