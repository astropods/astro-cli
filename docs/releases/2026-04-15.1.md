# Release — 2026-04-15.1

## Managed Knowledge Stores

You can now provision managed knowledge stores directly from the CLI. `ast knowledge create` spins up a database (Postgres with pgvector, Qdrant, Redis, or Neo4j) inside your agent's infrastructure and wires it into your agent automatically. Supporting commands — `list`, `status`, `logs`, `credentials`, `delete` — give full lifecycle control. All output supports `-o json` for scripting.

Postgres stores auto-derive the database name from the agent name (`memory-box` becomes `memory_box`) and inject `POSTGRES_DB` into both the knowledge container and the agent. The default Postgres provider now ships with pgvector (pg17) for vector search out of the box.

**External knowledge stores:** If you already run your own database, `ast knowledge connect` registers it with Astro. For private databases, PrivateLink automation handles VPC endpoint creation, security groups, and DNS — with pre-flight validation for AWS account limits before any resources are created.

## Live Log Streaming

The Logs tab now supports real-time tailing. Clicking the tail button opens an SSE connection to the server, which relays events from Loki (or falls back to Kubernetes). New log lines appear instantly with auto-scroll. Connection state is visible in the UI — connecting, streaming, and reconnecting states are all surfaced.

Logs are now returned as structured JSON (`timestamp`, `level`, `message`) instead of plain text. Level normalization maps raw values like `warn`, `err`, and `crit` to canonical levels, and the log viewer supports filtering by level.

## Compute Limits

The deploy page now proactively warns you when your organization has reached its compute limit. A banner appears at the top of the deploy form with a "Request quota increase" button that opens an in-context dialog. The deploy button itself is disabled with a tooltip explaining why. Successful quota requests show a toast confirmation.

## Badge System

Status indicators across the app have been unified into two primitives: `StatusBadge` for semantic status (success, warning, error) with an optional animated dot, and `Tag` for flat category labels (teal, blue, yellow, coral). All deployment status, trace status, history status, and privacy indicators now use these shared components.

## Blueprint Improvements

**Archive:** Blueprint owners can archive a blueprint from the kebab menu (⋯) on the detail page header.

**Name availability:** The creation flow now checks name availability as you type and disables the create button if the name is taken.

**Onboarding polish:** Draft cards use a dashed border with a soft yellow "Finish setup" pill. The setup panel's command blocks have cleaner formatting. Confetti fires within the creation panel on success.

## Variables & Secrets

The secrets and variables UI has been reworked. The "New variable" modal now has a single "Secret" toggle instead of separate flows. Descriptions can be edited inline. The vault picker includes a "New variable" shortcut. 1Password autofill is suppressed on value fields.

Config values entered in the CLI or UI are now trimmed of leading/trailing whitespace, preventing "invalid token" errors from copy-paste.

## Fixes

- Acronyms in variable field labels are now capitalized correctly (API, ID, URL, OAuth)
- Username minimum length validation aligned between client and server (4 characters)
- Viewport meta tag and page titles added to all routes
- Blueprint card name no longer overlaps with the private badge or kebab menu
- Loki level detection works correctly with Loki 3.x auto-detected levels
