# Release — 2026-05-23.1

## Pod Workload Metrics

The pod detail panel gains a Metrics tab with live CPU and memory charts for the selected pod, sourced from the central Prometheus that already aggregates cAdvisor scrapes from every cluster. A small range picker (1h / 6h / 24h / 7d) at the top of the tab swaps the window; each range picks a step that keeps charts at ~100–250 points. With no data in the window the tab shows "No data in this range." rather than erroring. Storage charts are flagged as a follow-up (the kubelet volume metrics aren't on the keep-list for agent clusters yet).

## Network Traffic on the Agent Monitor Page

The agent Monitor page has a new Network Traffic section, peer to Token Usage / Requests & Latency / Traces. Three summary cards (Inbound / Outbound / Database) show request count plus sub-metrics, with a per-direction top-peers table beneath. The Responses column renders a stacked horizontal bar (success / 4xx / 5xx) plus a `99.5% ok` label; hovering surfaces exact counts. The shared 7D/14D/30D selector at the top of Monitor drives every panel together — including this one — so range changes refresh all sections at once.

Under the hood, three new per-deployment endpoints (`/network/summary`, `/network/flows`, `/network/timeseries`) read Beyla eBPF-derived HTTP/DB metrics from Prometheus. v1 covers inbound HTTP, outbound HTTP, and database; RPC is intentionally deferred until label and bucket compatibility is validated. Outbound HTTPS from Bun runtimes is also not yet instrumented — those agents show an empty state for outbound.

## Per-User Cost View

The Insights page has a new **By Agent** / **By User** toggle. By User groups spend by WorkOS member, with an "Agents Used" column that resolves cross-account avatars correctly (a public blueprint deployed under your org renders the publisher's avatar, not a placeholder). Traces without a member-linked identity are split into two distinct buckets — **Unauthorized** (a real user from an adapter like Slack that hasn't been linked) and **Unattributed** (no user at all, e.g. background jobs / cron / SDK) — instead of being collapsed into one "Unknown."

Historical traces from undeployed agents no longer inflate account-level totals on either view; account aggregation now scopes to deployments with `status != 'undeployed'`. This silently corrects past-period numbers for accounts with deleted deployments.

## Insights Performance and Hardening

Account-level summary endpoints stopped fanning out per deployment for the bulk of their work. The account-summary endpoint now runs three batched Langfuse queries (down from `2N + N`); the blueprints-summary endpoint dropped the per-deployment P95 query to one batched call (`2N → N+1`). Both handlers gain a 30-second request timeout and a 100-deployment fan-out cap. A new `total_tokens` field on the summary responses becomes the source of truth; `input_tokens` / `output_tokens` are still populated and clients fall back to summing them. Org-switch and date-range changes paint faster.

## Per-Agent Infrastructure Usage

Two new endpoints query raw compute consumption directly against the OpenMeter `compute` meter, bypassing the entitlements layer:

```
GET /api/v1/accounts/:account/usage/infrastructure?from=&to=
GET /api/v1/agents/:account/:name/usage/infrastructure?from=&to=
```

Both return `{account_id, from, to, usage: {deployment_compute}}`. The agent endpoint sums across all deployments of the named agent for the account and returns 404 if the agent doesn't exist. The `usage` wrapper is extensible — knowledge compute and storage will be sibling keys in a follow-on. `from`/`to` are optional RFC3339; both default to start-of-month through now.

A separate fix lets the agent endpoint succeed for cross-account blueprints: the per-agent infrastructure usage query no longer rejects requests when the blueprint lives in a different account than the requester (billing is already attributed to the hosting account via `deployments.account_id`).

## Account Cluster Placement

Queen operators can now bind an account to an additional cluster. Deploy and deployment-template generation inject `target.cluster_id` from that binding server-side, so the CLI stays cluster-unaware. Accounts with no binding continue to route to the primary cluster. Cluster mutations remain blocked on the read-only `primary` entry. The Queen Clusters admin page also gained health-check error display and editing for the existing cluster fields.

## Connectors Settings

GitHub and Slack identity links moved out of the personal Account settings page into a dedicated `/settings/connectors` page (`Plug` icon in the nav, between Variables & Secrets and Organizations). Both connectors now share the same row shape: brand icon, status line, action area. The GitHub card shows one row per granted org (avatar + login); Reauthorize broadens scope, Disconnect uses the existing type-to-confirm dialog. The Slack card surfaces workspace icon + team name, `@username`, and a copy-to-clipboard button for the Slack user ID (the ID itself stays hidden). Slack description copy now clarifies the connector maps Astro identity → Slack identity for inbound auth resolution; it is not for outbound impersonation. OAuth callback redirects (`?github_connected=…`, `?slack_connected=…`) return to the new page.

## Navigation Progress Bar

The top-of-viewport progress bar replaces its perpetual 1.1s sweep with an nprogress-style state machine: jump to 15% on click, trickle slowly toward 90% while the navigation is pending, snap to 100% and fade on completion. A 50 ms navigation gets a quick snap-to-done; a 5 s navigation gets a slow burn that's still moving. Same UX pattern GitHub and Turbo use.

## Deploy and Configure Fixes

- Configure pane no longer shows stale grants after a redeploy. The deploy-template cache is now keyed shared with the deploy path, so a successful deploy evicts every cached entry for that deployment and the next configure prefill re-fetches live grants.
- The **Upgrade to newest build** modal on deployment cards confirms correctly again — it now navigates directly to `…/configure?build=<latestBuildId>` instead of a dead router state from the agent-detail redesign.
- The agent detail badge no longer shows **Active** (green) while workload containers are still starting. `mapDeploymentStatus` now returns **Deploying** when any Deployment/StatefulSet container isn't ready or pause/resume replica counts disagree. Closes one slice of the broader "Slack traffic ready" mismatch; the remaining gaps (DB `active` vs rollout, application-level readiness signals) are tracked as follow-up.
- The GitHub Connect modal's path field is now below the branch selector (branch is the primary choice, path is the optional refinement) and its placeholder reads `e.g. services/my-agent` instead of looking like a real value.

## Org Invite Acceptance

Accepting a WorkOS org invite no longer redirects back with `invalid_state` or leaves the user on the wrong account. Invite acceptance is now routed through Astro's `/auth/login`, which forwards the `invitation_token` to WorkOS's authorization endpoint inside the normal OAuth flow — state is generated and cookied before WorkOS is involved, so the callback's CSRF check passes and the new membership is synced as part of the same session.

## Network Metrics Selector Fix

The deployment-scoped network metrics endpoints initially queried a Prometheus label (`agent="<account>.<agent-name>"`) that Beyla never emits, so every panel returned zero. They now select on `k8s_namespace_name` + `service_name` — the same labels the OBI Grafana dashboard filters on. The namespace anchors the query to a tenant and `service_name` (set to `app.kubernetes.io/name` = `SanitizeName(agent)`) disambiguates agents within it.

## CLI 0.13.2

`ast push` now accepts `dev.interfaces.messaging.slack.observe_channel_ids` (the field was added to the Go schema earlier but `astropods.schema.json` had not been regenerated, so installed CLIs rejected it). Run `ast upgrade` to pick up the fix. The interactive `ast account switch` picker also gains an `esc to quit` binding and visible hint — previously only `ctrl+c` would dismiss it.

## Node Network Interceptor — Design Spec

A spec lands for a zero-touch network-layer interceptor for Node agents. Design only — no runtime change in this release. The interceptor will preload via `NODE_OPTIONS=--require=…`, patch `undici` + `http`/`https.request`, route LLM provider traffic through the Astro AI proxy with attribution headers, and extract `gen_ai` token usage for Anthropic + OpenAI. Delivery is via the astro-registry mirror serving pre-patched versions of common Node base images under their canonical Docker Hub paths — `FROM node:20` resolves transparently to the instrumented variant. Opt-out via a new optional `agent.instrumentation: false` field in `astropods.yml`.

## Appendix

**Commit range:** `5e86d94a..e839be09`

**Workload metrics**
- New `GET /api/v1/deployments/:id/pods/:pod/metrics?range=1h|6h|24h|7d`. Re-uses `resolveDeploymentContext`; runs two parallel Prom range queries — `sum(rate(container_cpu_usage_seconds_total{...}[N]))` for CPU and `sum(container_memory_working_set_bytes{...})` for memory — scoped by `namespace`/`pod` and `cluster`.
- Range presets: 1h/30s, 6h/2m, 24h/10m, 7d/1h. `rate()` lookback always ≥ 2× step.
- FE `PodDetailPanel.tsx` Metrics tab between Logs and Events; `PodMetricsTab.tsx` renders two Area charts with React Query polling (30s for 1h, 60s for 6h, 5min for 24h/7d).
- Storage deferred: `kubelet_volume_stats_used_bytes`/`_capacity_bytes` aren't in Alloy `prometheus.remote_write` keep-list on agent clusters; tab footer notes "coming."

**Network metrics API + Monitor UI**
- Three endpoints under `/deployments/:id/network`: `summary`, `flows?direction=…`, `timeseries?direction=…&metric=…&group_by=peer|status_class`. `direction=inbound|outbound|database`.
- `directionSpec` is a list per direction so additional metric families can be unioned in once compatible. RPC excluded from v1 (label set + bucket boundary divergence vs HTTP).
- Server-side `topk(8, …)` cap on peer-grouped timeseries so high-cardinality outbound destinations can't blow up the response. Status-class folding done in Go after matrix arrives.
- New `promquery.QueryRange` + `MatrixSample`/`Point` for `/api/v1/query_range`. New `resolveDeploymentContext` parallels `resolveLangfuseContext`.
- Label selector switched from `agent="<account>.<agent>"` (Beyla doesn't emit) to `k8s_namespace_name + service_name = SanitizeName(agent)`. Matches the OBI Grafana dashboard query pattern. Tests updated to assert the new selector shape.
- FE: `useNetworkSummary`/`useNetworkFlows`/`useNetworkTimeseries`; `staleTime: 0` for live, `5m` for flows. `NetworkSummaryCard` (Inbound/Outbound/Database) and `NetworkFlowsTable` (direction-pill-switched, stacked horizontal bar for response classes). Direction pill reuses `TimeRangeSelector` with `NETWORK_DIRECTIONS` + distinct `layoutId`. `networkKeys.flows` cache key extended with `limit`.

**Insights — per-user view + correctness**
- New `GET /accounts/:account/observability/users-summary` returning per-user `requests/cost/tokens/last_seen/agents_used`. Two parallel Langfuse queries (`Q_main` dims `[userId]` daily, `Q_tags` dims `[userId, tags]`) merged in `buildUsersSummary`. `agents_used` deduped by `account/name`, capped at `maxAgentsPerUser = 10`. `view: "traces"` (not `observations`) to avoid intra-trace double-counting.
- `GET /accounts/:account/observability/summary?group_by=user` adds `cost_over_time_by_user`; blanks `cost_by_model` in user mode. `metricsTimeRange(from, to)` helper substitutes 5-year lookback for empty timestamps so `/api/public/metrics` doesn't 400 on `?range=all`.
- Tag-shape defense: `tagStrings(v any) []string` handles Langfuse returning `tags` as either string or array. Regression test `TestBuildUsersSummary_TagsReturnedAsArray`.
- Deleted-deployment scoping: `mergedDailyMetrics(ctx, …, visibleDepIDs, from, to)` replaces single `GetDailyMetrics(account)` call. Fan-out bounded to 10 concurrent. Returns `activeDeps` derived from trace presence. Partial-fail logs warning; all-fail returns error. Tests: `_MergesPerDateAndTracksActiveDeps`, `_AllFailReturnsError`, `_PartialFailReturnsNoError`.
- Unauthorized vs Unattributed: `classifyUserId(uid, memberIds)` in `user-classification.ts`; consumed by `UserFilterBar`, `buildUserCostOverTime`, `TopSpendersTable`. Server-side `normalizeUserID(s)` maps SDK `"-"` sentinel to `""` at every Langfuse read.
- `depToAgent` is `map[string]UserAgentRef { Name, Account }` carrying publishing account; batched `accountStore.GetByID(...)` lookup. `UserSummaryEntry.agents_used` schema `[]string → []UserAgentRef`.
- `AgentsUsedChips` dropped `account` prop — per-entry now.

**Insights perf / hardening**
- `GetAccountLangfuseSummary` per-deployment `/metrics/daily` fan-out (`2N`) → two batched `/api/public/metrics` calls (`accountDailyMetrics`): traces view grouped `[tags, time]`; observations view grouped `[providedModelName, time]`. Net: `2N → 3` per request. Prior-period query stays fail-open.
- `GetAccountBlueprintsSummary` per-deployment P95 → one batched `/metrics` grouped by tags (`batchedP95Latencies`). Per-(deployment, model) cost fan-out remains because observations view doesn't support `tags` as a grouping dimension. Net: `2N → N+1`.
- 30s `context.WithTimeout` + `maxDeployments = 100` on `GetAccountLangfuseSummary`.
- `total_tokens` added to `AccountSummaryTotals`, `BlueprintSummaryEntry`, `BlueprintDailyTokens`. Drops old `input_tokens: totalTokens, output_tokens: 0` hack in `recomputeTotalsFromUsers`. FE `StatCards`/`DashboardStats`/`use-insights-data.ts` prefer it with input+output fallback.
