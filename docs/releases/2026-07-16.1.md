# 2026-07-16.1

## Chat: attach files, keep drafts, pop out a window

Chat gains file exchange and a batch of composer quality-of-life fixes.

- **Attach files to a message.** Drag-and-drop, paste, or use the paperclip to stage files on a message; they upload when you send and ride along as the agent's context for that turn. Files the agent produces come back as download chips on its reply.
- **Your files are yours.** Uploaded and agent-produced files are scoped to the person in the conversation — another user of the same account can't see or download them, and their existence never leaks across users.
- **Storage warnings.** The chat and Monitor screens warn when a deployment's disk is filling up (above 85%, escalating past 95%), and an upload that wouldn't fit is rejected up front with a clear "storage is full" message instead of a generic error. The banner clears itself once space is freed.
- **Composer picks the right state per conversation.** Switching between conversations no longer shows the wrong Stop/Send button, drops a streaming reply, or loses an unsent draft — each conversation keeps its own draft (surviving reload within the tab), and a reply that finishes in the background is still there when you return. A stalled turn now times out cleanly so you can resend.
- **Window controls.** The composer takes focus on load so you can type immediately, the header shows the conversation's title, and an "open in new tab" affordance detaches a chat into its own window.
- **Cleaner details inspector.** The Details panel packs configuration more densely: long system prompts stay contained and scroll internally, tools expand on demand with selectable descriptions, and section headers share one consistent treatment.
- **Dark-mode surface polish.** Dropdowns, selects, and overlays read as distinct layers in dark mode, and highlighted rows are clearer in both themes.

## See usage from local AI coding tools

Astro can now ingest usage telemetry from AI coding tools your team runs locally (starting with Claude Code) and land it in observability alongside your deployed agents.

- **Ingest keys.** A new **API Keys** section in personal and organization settings mints account-scoped ingest keys and renders a ready-to-paste managed-settings block. Keys are ingest-only (no read access) and individually revocable.
- **What's captured.** Sessions, tokens, cost, tool activity, and request traces flow in; prompts and source code stay off by default. Traces land in your existing trace views (tagged so coding-tool activity is distinguishable) and metrics go to the usage store.

## Insights: cost and latency per model

The Insights page gains a **Models** view alongside People and Agents: each model's request count, spend, spend share, token volume, and p95 latency for the selected window. Model names show the clean family name with the full versioned id on hover.

## Recover from a stuck deployment

When a deployment hangs while deploying, recovery is now front and center instead of locked out.

- Pause, Redeploy, and Restart stay enabled throughout a deploy.
- A banner appears as soon as Kubernetes reports a real problem (failed scheduling, image-pull failure, crash loop) and names the cause in plain language; a five-minute age backstop catches silent hangs, measured server-side so it's correct across reloads.
- The banner leads with **Roll back** to the last clean version (Pause alongside) and links to a new "Troubleshooting stuck deployments" guide.

## Deployment configuration

- **Longer response timeout.** Agents that take more than 15 seconds to respond were being cut off with no recourse. A per-deployment response-timeout knob in Advanced sizing now defaults to 15s and can be raised up to 2 minutes.
- **Clearer deploy phases.** The build-in-progress card (Preparing/Building) is now blue and the live Deploying tile stays amber, so stacked phases read as distinct; the two never show as duplicate in-progress boxes.
- **Access control for custom interfaces.** The deploy form's custom-interface section gains the same "Who has access" editor as messaging chat — Astro members, Public, or Invited only (per-org/per-user grants). (Grants are recorded now; request-time enforcement of specific-user grants for custom interfaces is a follow-up.)

## Publish agents to the open web

The AI Gateway keys Astro issues per tenant are unchanged in how apps use them (OpenAI SDK, a base URL, a bearer key, the same friendly model names). Behind the scenes, key issuance moved to a new gateway backend; this is transparent to deployed agents.

## Self-hosted: run unmetered

Self-hosted and OSS deployments can now run with no metering backend while per-account quotas stay enforced, selected with a `BILLING_PROVIDER` setting. Resource limits (agents, builds, deployments, members, knowledge stores) are now database-backed and configurable per account.

## Fixes

- The "returning visitor" marker that shows **Log in** vs. **Get started** on the marketing site is now set reliably at the server, fixing cases where the wrong call to action appeared.
- Deploy-form secret auto-fill no longer briefly pulls API-key values from the previously selected account while switching accounts.
- The messaging-adapter validation error on the deploy form now renders as inline text (matching other field errors) and highlights the interface group that needs attention.
- Very long deployment names no longer break dashboard cards, the reveal, or the shareable badge; names are capped at 42 characters with inline validation.
