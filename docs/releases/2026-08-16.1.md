# 2026-08-16.1

## Spend controls and pay-as-you-go

Every new account now starts on a plan with $10 of free credit, and the platform
knows what to do when that credit runs out.

- **Free credit, then a card.** An account that spends its credit without a card
  on file has its agents stopped and its managers notified. Adding a card lifts
  the stop, restarts the agents, and moves the account onto pay-as-you-go at the
  same rates. No plan change and no re-signup.
- **Set your own warning and limit.** A Spend controls card on the billing page
  shows what you have spent this period and lets you set a warning threshold and
  a hard spend limit. Leave a field empty to remove that control. A warning only
  warns; only the limit stops anything.
- **See your spend and your credit.** Current-period spend and remaining credit
  are on the billing page. The Credits & Commits tab now shows a readable table
  of name, granted amount, remaining balance, and expiry, in dollars.
- **Refusals say what to do.** A request refused for billing now names the fix:
  add a first card, update the card on file, or contact support. The agent
  toggle, the deploy form, the banner, the per-agent tooltip, and the CLI all
  draw the same instruction from the same place, so they cannot contradict each
  other.
- **A stopped agent says it was stopped by billing.** It previously read as
  "Starting" with a toggle you could flip. The agent now shows a distinct
  Suspended state, the toggle is disabled, and the chat composer explains why.
- **Links go to the account that is actually affected.** An organization's
  billing banner and its billing notifications now open that organization's
  billing page rather than your personal one.

Billing enforcement is live in preview only. Production is unchanged.

## Fine-grained deployment access

Organizations can now give individual people access to individual agents instead
of relying on account membership alone. Turn on **Fine-grained access** under
Organization Settings → Experiments.

- **Three roles per deployment.** Viewer can read. Builder can read, edit,
  operate, and delete. Owner adds the ability to grant access to others.
- **Private by default.** Owners and admins keep access to everything, the
  person who deployed an agent becomes its Owner, and other members get nothing
  until someone grants it.
- **Off means nothing changes.** With the switch off, access works exactly as it
  does today. Turning it off again restores that behavior immediately.

The access-management screens ship in a later release. Production keeps
fine-grained access disabled.

## Insights

- **Claude Code spend is real spend.** Token counts from Claude Code now reach
  the platform in a form it can price, so dev-tool cost, request counts, cost per
  request, and tokens per request are all populated instead of showing zero.
  Historical Claude Code spend does not carry over; the record starts from this
  release.
- **Faster Insights.** A new experiment under Settings → Experiments points the
  page at a durable daily store instead of recomputing 90 days of history on a
  six-hour cycle. Enable it to compare, disable it to go back.
- **The page reports the window it actually covers.** Charts no longer end on a
  permanently empty day, and period-over-period change is compared like for like
  instead of being biased low by roughly a day.
- **Last used replaces p95 latency** in the Agents and Models tables.
- **Rename a data source in place.** A typo no longer means revoking the key and
  reconfiguring every machine that uses it.

## Evals

The review queue is now about dataset membership rather than grading.

- **Add to dataset or Remove**, in place of Good, Bad, and Not sure. The dataset
  table lists traces as members, with no verdict column.
- **Record each criterion as positive or negative.** Criteria you do not select
  are left unrecorded rather than counted against the trace.
- **Criterion distributions.** The dataset summary shows each criterion's
  positive and negative counts, its ratio, and a distribution bar, each measured
  against its own total.
- **Judged or Not judged.** The AI judge reports whether it analyzed a trace,
  with its confidence, explanation, and per-criterion assessment. It no longer
  offers an overall verdict.
- **The judge reads the conversation.** Predictions now consider the three turns
  before the target trace, so a short follow-up answer is no longer marked wrong
  for lacking context its question already supplied.
- **Keyboard review.** Arrow keys move through the queue and shortcuts record
  actions without leaving the keyboard.
- Reviewers get a toast when a judging run finishes, including a partial result,
  a one-time tip on the Run AI Judge button, and real avatars in the queue.

## Your agents, blueprints, and knowledge stores

The multi-account list filter is back, rebuilt so it stays fast.

- **One page across every account you pick.** The server returns a single ordered
  page rather than walking each account separately in your browser, and the first
  page arrives with the HTML.
- **Search covers everything selected**, not just the rows already on screen.
- **Pages open on your personal account** and remember the account filter you
  last used on that page.
- **Filter agents by status.** An All / Active / Stopped / Error control sits in
  the toolbar and is remembered between visits.
- **Typing in a search box no longer stalls the page.** Keystrokes cost nothing
  until the term settles, and the Agents page no longer freezes on load while
  starfield animations start on cards nobody is looking at.
- **Blueprint pages name their owner.** The detail page title reads
  `account / name`, and every card footer shows the owning account.
- Account switchers stay visible on an empty page, so a new user can move to
  another account from the onboarding state.

## Deploying and running agents

- **Cancel a deployment that is stuck coming up.** Previously a hung rollout
  blocked redeploys for about half an hour until Kubernetes gave up.
- **Pick the model in its own section.** A gateway model choice is now real
  configuration with a dropdown, not a synthesized entry under "Optional
  credentials".
- **Clear an optional variable.** Emptying a field and redeploying now removes
  the value instead of silently restoring the old one.
- **A finished build appears without a refresh.** The deploy page picks up a
  completed build as the next upgrade, and the available build shows the same
  branch and build id as the deployed one.
- The Deployments tab shows "Deploying your agent" during a fresh deploy instead
  of looking blank, the stuck-deploy banner is trimmed to two clear actions, and
  image-pull guidance now names something you can actually do.
- **Load older logs** is an explicit button, and prepending older entries no
  longer jumps you to a different timestamp.

## Monitoring

- **See the shape of an agent's traffic.** The Network Traffic section leads with
  a graph: inbound routes on the left, outbound destinations on the right, sized
  by request volume. Destinations for the same vendor merge into one bubble.
- **126 new brand icons**, weighted toward what agents actually call: inference
  providers, vector stores, observability backends, and payment and email APIs.

## Chat

When an agent asks you something inline, the chat now records how you answered.
A form submission or a tool approval appears as a short note, a written reply
appears as your message, and the agent's follow-up opens a new bubble instead of
extending the text that preceded the question.

## Knowledge stores

Astro AI no longer provisions databases. Every knowledge store is a database you
already run, connected with credentials Astro AI holds encrypted. The create
endpoint, the store Logs tab and event timeline, and `ast knowledge create` and
`ast knowledge logs` are removed. Connect, list, status, credentials, delete, and
bindings are unchanged.

## Notifications

Notifications are now enabled in production.

- **Deployment alerts go to the people who touched the agent.** Deploying,
  configuring, or operating an agent makes you a watcher of it, and its alerts go
  to its watchers. An agent with no watchers yet still notifies account managers,
  so nothing goes unsent.
- **Alert text reads as claim, evidence, fix.** Each alert states what is
  happening, the number observed, and one thing to do. Titles name the problem:
  "Frequent restarts", "Near memory limit", "Slowed by CPU limit", "Unused CPU".
- **Build failures explain themselves.** A spec problem names the file, the line,
  and the message. Compiler and network output is no longer forwarded into your
  inbox.
- Fixed two messages that arrived with a blank in them: a revoked ingestion key
  now names the key, and a suspension notice names the account.

## Fixes

- Agents on managed clusters outside the primary region could not pull their
  images, and agents on IPv6 clusters had no DNS or outbound network at all.
- In-app chat now reaches an agent over a private network path instead of the
  Kubernetes API, which hung on IPv6 clusters and could be blocked on any managed
  cluster.
- Billing suspension could not actually stop almost any agent, and no billing
  event from the provider had ever been accepted, so credit exhaustion never
  gated anything.
- Rolling back a deployment checked its state before checking whether you were a
  member of the account, which leaked that state to any authenticated caller.
- Deploying an agent bound to a connected knowledge store failed in a local
  environment with a misleading AWS credentials error.
- Deregistering a cluster was blocked by agents that had already been torn down.
- The Agents page could stall on an account with 50 to 60 agents.
- The chat tab served by the CLI showed a blurry favicon.

## Admin console (Queen)

- **Billing operations on the account page.** Provisioning state, contract
  coverage, credit remaining, the open period's draft total, and the last
  invoice, with deep links to the right Metronome and Stripe environments, plus
  two repairs: re-run provisioning and force a billing resume.
- **Clusters are read-only and self-registering.** Cluster connectivity now comes
  from infrastructure config at server boot, so the register, edit, enable, and
  disable actions are gone. The detail page shows every field, health-checks each
  configured URL, and can re-push a cluster's registry pull credential after a
  rename.
- **Configuration drift checks.** A new Evaluators panel on the Deployments page
  finds deployments whose configuration has fallen behind a platform migration
  and fixes them one at a time or all at once. The first check covers routing for
  in-app chat.
- **Outbound domain coverage.** `queen <env> icons domains` reports every
  destination agents reach fleet-wide, so brand icons get authored from real
  traffic.
- Changing an account's cluster no longer forces an immediate migration of
  everything it is running; migration is a separate action.
