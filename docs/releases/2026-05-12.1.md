# Release — 2026-05-12.1

## Public Account Profiles

Every account — personal or org — now has a public profile page at `/{handle}` with bio, location, pronouns, website, social links, and tabbed Blueprints / Agents / Hearts views. Owners can drag to reorder blueprints, preview the page as a visitor, and edit profile fields inline from a unified sidebar. The first 1000 accounts get an early-adopter badge. The standalone Profile tab in Settings is gone — the profile page is the only editing surface now. Public blueprint READMEs gain LinkedIn and X share buttons.

## Authorization Grants and Slack Identity

Deploy forms have a new inline editor for choosing who can use each adapter — Anyone, members of an org, or specific users. The web/OIDC toggle is gone; web auth is always OIDC. Slack now supports per-user grants: users link their Slack workspace(s) from account settings, and per-user Slack grants resolve through that mapping. Fresh deployments seed sensible defaults (the deploying user for web, anyone for Slack). The grants editor warns when a Slack grant targets a member who hasn't linked Slack yet, and owner fallback is now scoped per-adapter so a Slack grant no longer locks web for owners (and vice versa).

## Knowledge Stores

MySQL joins Postgres, Redis, Neo4j, and Pinecone as a supported provider in connect-your-own mode; platform-managed knowledge store creation is off by default. The Add Store wizard is connect-only with cleaner copy and a public-vs-PrivateLink picker. The deploy-form binding picker has clearer Shared vs Local labels with proper empty states and can clear all bindings on redeploy. Deleting a store with active bindings now lists the blocking agents instead of returning a generic error. Entitlement limits on store count, storage, and endpoints are enforced on creation, with real error copy.

## Agent Detail Page and Observability

The agent detail page is rebuilt with a tabbed Deployments / Monitor / Configure layout, an immersive header, and a pod-graph visualization. The trace side panel becomes a Langfuse-style viewer with a timing waterfall, observation tree, and tabbed overview. Latency charts now show real per-bucket P95/Min/Max instead of placeholder zeros, and monitor axes always render even when the time window is empty. Deployments fail fast on missing container images with an actionable message and a one-click "upgrade to latest build" affordance, so deploys no longer hang in "Deploying" on a bad image. Scheduled ingestion runs (cron) are first-class in the deployment view.

## CLI and Local Development

`ast project create` is now a non-interactive command that takes a kebab-case name, asks for a goal once, and prints a context-rich prompt to paste into your IDE assistant. `ast project start` runs in the foreground by default (`-b` for the old behavior). Long Docker builds emit periodic heartbeats so they no longer look stuck. `ast push` respects the build-time registry URL after the `astropods.com` domain migration and survives long uploads through the registry's new token-auth flow. Public Fern docs are fully rewritten to match the current command surface. A new `scripts/local-dev.sh` starts Traefik, server, client, and a local `ast-dev` binary in one command.

## Org Admins, Permissions, and Vault

Org admins (not just owners) can view and submit quota increase requests. The Usage page is now available under org settings, not just personal. Vault access is gated on dedicated `variable:read` / `variable:write` permissions held by owner and admin roles. The "+ New" variable button is hidden for org members who would be rejected, and the scope auto-switches when an admin or owner deploys against a different org. Vault load errors surface inline with a real message. The scope switcher shows display names instead of handles.

## Metering and Billing

Compute usage is now metered from real deployment lifecycle events instead of the 5-minute heartbeat — short-lived deployments and crash recovery no longer over- or under-count. The account usage endpoint returns all subscribed meters dynamically, including knowledge store meters, instead of a hardcoded four.

## Theme, Dark Mode, and UI Polish

A coherent slate + indigo palette replaces the previous stone + teal across the app. Dark mode renders correctly on first paint with no flash, mirrored through a cookie at SSR. Trace status badges, AGENT.md code blocks, GitHub brand chips, blueprint cards, deploy reveal overlay, and settings tables all have proper light and dark treatments for the first time. Blueprint detail breadcrumbs link the account crumb to its profile and mirror the referrer (Explore vs. Blueprints) at the root.

## Deployment Lineage and Reliability

Deploying a public blueprint from another account uses the deploying user's account for variable lookups (no more empty or forbidden vault references). Configure-page redeploys of private org-owned blueprints no longer 404. Forked repos and org repos now appear in the GitHub repo picker. Stale GitHub tokens surface as a reconnect prompt instead of a 500, and a WorkOS-expired session redirects to login instead of showing a refresh hint.

## Migration

| Change | Action |
|---|---|
| New vault permissions `variable:read` / `variable:write` | Operators must add both slugs in WorkOS for the owner and admin roles, otherwise vault becomes inaccessible |
| Slack OAuth env vars | Set `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_CALLBACK_URL` on the server |
| Managed knowledge stores | Default-off; set `KNOWLEDGE_ALLOW_MANAGED_CREATE=true` to restore the previous behavior |
| Account usage endpoint response | Shape changed from four named fields to a `meters: {key: {usage, quota}}` map — clients reading the old fields must migrate |
| Registry token auth | Set `REGISTRY_TOKEN_SECRET` on `astro-registry`; CLIs older than this release will fail to push |
| Spec field rename | `grants[].account_id` → `grants[].org`; old field no longer accepted |
| GitHub OAuth scope | The WorkOS GitHub app now needs `read:org` to enumerate org repos |
