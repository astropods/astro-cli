# 2026-06-10.1

## AI Gateway

A new managed model gateway is available. Opt in by setting `agent.astro_ai_gateway: true` in `astropods.yml`; the agent container then receives `ASTRO_GATEWAY_URL` and `ASTRO_GATEWAY_API_KEY` and the agent code picks the model at call time:

```yaml
agent:
  image: my-agent:latest
  astro_ai_gateway: true
```

- One opt-in covers every supported model — no per-provider credentials in the spec.
- Each deployment gets its own virtual key, minted on first deploy, reused on redeploy, and revoked on undeploy.
- Local `ast dev` mints a short-lived key automatically so the same agent code runs locally and in prod against the same gateway.
- The legacy `provider: anthropic-managed` shorthand is removed; the new opt-in replaces it.

## Deployment chat in the web UI

A new `/chat` surface lets any signed-in user message their agents directly from the dashboard, with history that persists server-side.

- Per-deployment conversation list with deep links (`/chat/:deploymentId?conversation=…`).
- Streaming responses render incrementally; closing the tab no longer cancels the turn — reopening tail-fetches and resumes.
- Eligibility filters the deployment list to agents with the messaging sidecar configured for web chat.
- Mobile gets a full-width list/thread swap below the `md` breakpoint; desktop keeps the sidebar.

## Eval datasets per deployment

Each deployed agent now gets an evaluation dataset provisioned automatically.

- A new **Eval** tab on the agent detail page shows the dataset name, item count, and last sync time.
- A nightly background sync keeps the dataset current with new traces; **Sync** triggers an immediate refresh and **Download** exports a JSONL archive.
- Sync is now idempotent: retries no longer create duplicate items, and partial failures are reconciled on the next run.

## Blueprints show your deployed agents

The blueprint detail page now lists the agents you've deployed from that blueprint across every account you belong to.

- Up to four rows by default with a "Show N more" disclosure.
- Scope is private to your accounts; nothing leaks about deployments owned by others.
- The scope explainer is now a click/tap popover so it works on touch devices.

## Knowledge Stores: visual polish

A pass across the Knowledge Stores list, detail, and new-store flow.

- Detail header consolidates provider + mode into a single chip, with the ARN/URL right-aligned and truncating cleanly on narrow widths.
- Settings tab uses a centered form layout. Credentials render as a divided table with per-row reveal and copy; a blurred-ghost preview shows the shape before reveal so the layout doesn't jump.
- Dark-mode parity for metric cards, agent bindings, event log, and the new-store provider list.
- Provider icons now resolve correctly for users on system-preference theme (previously some icons rendered light-on-dark).

## Insights polish

Two passes on the Insights page tightened identity rendering, table chrome, and progressive disclosure.

- Slack rows are visually consistent with Astro member rows; unlinked Slack users no longer feel like second-class entries.
- Unlinked Slack users in the People view now get their own rows with Slack profile names, avatars, and deep links when the workspace is known — including users active before this feature shipped.
- Long tables reveal more rows progressively (5 → 10 → all) with a short staggered animation.
- A new ranking column appears next to identities; the deployments table chrome matches the chart cards above it.
- "Show deleted agents" and the legacy unidentified-aggregate row are removed.

## Build & dev fixes

- **`ast build` / `ast push` on Docker Desktop 4.77.0:** rewritten on top of BuildKit's gRPC endpoint, the same path `docker buildx build` uses. Trivial builds now finish in ~2s, cross-arch builds work natively, and the intermittent `archive/tar: invalid tar header` / "load remote build context" hang is gone. Run `ast upgrade` to pick up the fix.
- **`ast dev` postgres:** `POSTGRES_USER` and `POSTGRES_PASSWORD` are now auto-injected for container-mode postgres knowledge stores, matching the prod deploy path. Projects that worked around this can delete the `agent.inputs` workaround. If the workaround used `POSTGRES_USER: postgres`, see the migration note below.
- **Frontend agents** now receive `PORT` in the container env so frameworks that read `process.env.PORT` (Express, FastAPI/uvicorn, Next) bind to the right port without hardcoding.

## Fixes

- **Configure page:** select dropdowns now preserve their stored value when the page is reopened. Text inputs and other field types were already correct.
- **Cross-account deployment listing:** `GET /api/v1/deployments` accepts `?build_id=` without `?account=` and returns matching deployments across every account the viewer belongs to (used by the new blueprint sidebar).
- **Agents empty state:** when the selected account already has blueprints, the CTA now says "Deploy a blueprint" and links to the account's blueprints list. Previously it always said "Create blueprint" regardless of context.
- **Insights deep links:** unlinked Slack users without an exact directory hit now get a deep link inferred from the workspace when every other known Slack row in the same view shares that workspace.
- **CLI ↔ server credential parity:** the env-var names `ast dev` injects now match what the server injects on deploy. See migration below.

## Docs

- New **Guides → Messaging SDK** section covers the gRPC protocol in both Node and Python.
- New **Guides → Adapters** section covers the framework-adapter layer with quickstarts for Mastra and LangChain plus custom-adapter guides for both languages.

### Build path migration (#1316, #1319, #1322)

- #1316: pinned `docker/cli` v29.5.3, `docker/compose/v5` v5.1.4, `moby/buildkit` v0.29.0, `moby/moby/api` v1.54.2, `moby/moby/client` v0.4.1. Direct `docker/docker` dep dropped. CLI 0.15.1 → 0.15.2.
- #1319: stop-gap — skip BuildKit when no secrets declared (`needBuildKit := len(secrets) > 0`). CLI 0.15.2 → 0.15.3.
- #1322: real fix. Two root causes stacked.
  1. **gRPC codec collision.** `packages/astro-proto/admin/v1` and `connect/v1` registered a JSON codec with `Name() string { return "proto" }`, hijacking gRPC's default proto codec process-wide. `astro-cli` imports `connect/v1` for device-connect, so BuildKit's session `grpc_health_v1` server inherited JSON unmarshalling on protobuf bytes; Docker 4.77.0 tightened the health-check timeout and detonated it. Codec renamed to `"json"`; clients opt in via `grpc.WithDefaultCallOptions(grpc.CallContentSubtype("json"))`. Unit tests + a `codec-collision-guard` CI job reject any built-in codec name in `packages/astro-proto/`.
  2. **Legacy `/build` + `/session` path is structurally fragile.** Migrated `ast build` to `bkclient.Solve` against the daemon's embedded BuildKit gRPC endpoint (the buildx `docker` driver path). Exporter is `"moby"` (not the documented `"image"`) so the built image lives in the moby store and `docker image inspect` / `dockerCli.ImageTag` / `ast push` see it. Deleted `buildImageSDK`, `prePullBaseImages`, `parseDockerfileBaseImages`, `readDockerignore`, `streamBuildOutput`, and the `readyOnRead`/`readyOnWrite` race wrappers — net `-721/+75`.
- The #1319 BuildKit-skip workaround is reverted by #1322.
