# 2026-07-10.1

## Chat: durable, switchable, and voice-ready

The web chat experience gets a large pass on reliability, navigation, and input.

- **Voice input.** A microphone button in the composer transcribes your speech into the message box. Confirmed words land in the input while an in-progress caption shows what's still being heard; transcription runs entirely in your browser.
- **A focused details panel.** A **Details** toggle in the chat header opens an inspector with the agent's health, recent usage trends, latest traces, and read-only configuration (system prompt and tools). Traces link straight into the Monitor page, and you can open a specific trace and page through the rest.
- **Better agent switching.** The agent switcher groups agents by account, highlights the one you're chatting with, and moves per-agent actions into a kebab menu. When you have a single agent, the switcher offers a "Deploy more agents" shortcut. A one-time coachmark points new users to the switcher.
- **Clearer empty and error states.** Chat now distinguishes "you have no agents yet," "none of your agents can chat," and "we couldn't load your agents" (with retry), each with the right call to action.
- **Composer state matches the agent.** The composer shows a spinner while an agent is starting, disables with an explanation when the agent is paused/stopped/errored, and only enables when the agent is actually reachable. Slack-only agents no longer appear in the chat picker at all.
- **Stop generating actually stops.** The stop button now cancels the model call, keeps the partial reply, and ends the turn — instead of only closing the connection.
- **Reliability fixes.** First messages on slow connections no longer lose their reply, rename/delete on the history list no longer close unexpectedly or steal focus, and conversations survive reload with a durable fallback.

## Evals: judge production traces into datasets

The Evals tab gains a full review-and-dataset workflow for turning real traces into an evaluation set.

- **Review queue.** Work through production traces and grade each one **Good**, **Bad**, or **Skip** — by button or by keyboard (G / B / S). Each judgment animates toward the dataset grade badge, and an undo affordance appears right after you grade. Load more traces on demand; the full trace detail panel opens inline and follows your selection.
- **Optional criteria.** After grading, you can tag *why* a response was good or bad (accuracy, completeness, instruction-following, scope clarity, tone). Criteria show up in the dataset as an inline reason and a sidebar breakdown.
- **Dataset view.** Inspect added examples in a bordered table with verdict filters (Good / Bad), input/output, and who judged each item. A circular grade ring shows the current grade and how close you are to the next one, with guidance on what to do to improve it (grade more, add failure cases, reduce noise). Filtering by verdict now pages correctly through matching items.
- **Edit after the fact.** A row menu lets you change an item's verdict or edit its criteria in place.

## Monitoring: search, share, and navigate traces

- **Search** the traces table by span name, trace ID, user ID, or user name.
- **Copy a shareable link** to any trace; the link preserves the selected time window and opens straight to that trace.
- Traces load reliably even for large windows, with load-more pagination, and the table stays readable when the detail panel is open.
- **Container error indicators.** Container cards flag containers whose recent logs contain errors; clicking through opens the Logs tab at the offending line.
- **Clearer event messages.** Long Kubernetes event messages are expandable, pod scheduling failures (insufficient CPU/memory, taints) now read in plain language with guidance, and stuck deployments lead with "Action required."

## Every agent gets persistent storage

Every deployment now ships with a persistent 5Gi disk mounted at `/data`, shared with the messaging sidecar — there's no longer an enable/disable choice for storage. Chat history now lives on this disk rather than in the platform database.

## Deployment insight

- **Redesigned pod graph.** The deployment graph now uses a deterministic, columnar layout that follows the real data flow (ingestion → knowledge → agent → models/tools), with connecting lines and provider brand icons instead of a random constellation. It's pannable and zoomable on desktop (drag, wheel/pinch, fit button) and a natively scrolling list on mobile.
- **Always-visible Redeploy.** The Configure tab always shows a Redeploy action, so you can re-apply the current configuration without a throwaway edit. The button swaps to Save for name-only changes.
- **Launch button polish.** Launch stays visible but disabled with an explanation while a deployment is provisioning, undeploying, or errored, and its status updates correctly right after you resume a paused agent. It no longer appears on agents that can't serve web chat.
- Pod metric charts (Network, Filesystem) no longer clip their legends or axis labels, and paused deployments show a consistent paused state instead of briefly flashing "starting."

## Publish agents to the open web

Agent web surfaces — the messaging chat and custom interfaces — can now be made public and reached without signing into Astro. A **Protected** toggle (on by default) controls this; a custom interface set to public now stays public across redeploys.

## AGENT.md images and casing

- AGENT.md files can reference local images (e.g. `![diagram](./docs/arch.png)`); they're automatically uploaded to the CDN and render in the web app.
- READMEs named `agent.md`, `Agent.md`, or any other casing are now recognized.

## CLI: scaffold Gateway agents

`ast create --model gateway` scaffolds an agent wired to the Astro AI Gateway with no provider key required. (The `--model ollama` shortcut has been removed.) CLI is bumped to `0.15.5`.

## Knowledge stores connect reliably

- Agents bound to external or PrivateLink knowledge stores now receive full credentials (user/password/database), not just host and port.
- PrivateLink and plain external stores resolve to their correct endpoints, and a **Recheck connection** action repairs stores that cached a stale endpoint.

## Slack feedback scores your traces

Thumbs up/down and comments on an agent's Slack responses now attach a feedback score to the corresponding trace, so satisfaction shows up in observability.

## Blueprint build tracking

The blueprint's **Deployed agents** list shows each instance's build ID and an **Update** button when it's behind the latest build, and the agent detail panel shows in-progress build status above the active deployment. (The former "Upgrade" wording is now "Update" throughout.)

## Settings & accounts

- Personal account settings now show your username as a static `@handle` with a **Change username** link, matching organizations. Very long organization names wrap in settings and truncate with a tooltip in compact places; new org names are capped at 39 characters.
- Avatars load instantly from cache and update immediately when changed, across accounts, agents, and deployments. Profile and organization avatar uploads reflect in the UI right after they succeed, and badge PNG downloads keep the avatar image.
- Insights and Traces show Slack-only users with clearer labels and their Slack real names; the Insights table layout is tightened (no redundant "Rank" label, consistent sizing).
- The **Import variables** dialog hints at supported file types (`.env`, `.json`, `.txt`), and creating a new variable from a picker pre-fills the key and value you already typed.

## App now defaults to dark theme

New sessions start in dark mode by default.

## Marketing site

The marketing site is redesigned with a builders page and a stable `/home` route, and returning users see **Log in** while new visitors see **Get started**.

## Fixes

- Deploys no longer intermittently fail with a "Content-Length mismatch" error on EKS clusters.
- Redeploying an agent with a startup ingestion job no longer fails with an "object is being deleted" error.
- Signed-out visitors no longer see a Blueprints nav tab that would fail; public discovery stays available via Explore.

## Migration

| Change | Action |
|--------|--------|
| Default persistent disk | Agents are now StatefulSets with a retained 5Gi PVC at `/data`. Redeploy agents to adopt the shared disk. |
| Chat persistence | Chat now persists in the messaging sidecar on the shared disk; the previous database chat tables are removed. Apply `sql/astro-server/schema.sql` (Atlas), deploy astro-server, then redeploy agents so the sidecar and shared disk are in place. |
| Registry pull-through | Deploy **astro-registry before astro-server**. Set `PRIMARY_PULL_KEY_HASH` (registry) and `REGISTRY_PULL_CREDENTIAL` (server); apply the schema for `clusters.pull_key_hash`. |
| Public agent ingress | Set `AGENT_INGRESS_PUBLIC_DOMAIN` on astro-server to enable the open (no-sign-in) ingress cohort. |
| Knowledge bound credentials | Redeploy agents bound to external/PrivateLink stores so they pick up the full credential secret. |
| Schema | Apply `sql/astro-server/schema.sql` (Atlas) for the judgment-criteria table, pod-graph `provider` column, and avatar fingerprint columns before deploying. |

No action required for any other change.
