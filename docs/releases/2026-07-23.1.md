# 2026-07-23.1

## Deployment status you can trust

Deployment state is now driven by a controller that continuously watches the cluster and records what it sees, instead of being probed one request at a time. The result is status that is accurate, fast, and self-correcting.

- **"Active" means running.** A deployment flips to Active only once all of its workloads are actually up — not the moment the manifests are accepted.
- **Fails fast, with a real reason.** A rollout that can't succeed (unpullable image, crash loop, out-of-memory) now fails in about three minutes instead of hanging for ten, and the deployment card explains it in plain language ("Couldn't pull the container image", "The container keeps crashing on startup", "The container ran out of memory") instead of a bare "Error" or a raw Kubernetes code.
- **Shows what it's waiting on.** While a deployment is deploying, it now names exactly which workloads are still coming up rather than a generic "waiting for workloads" message.
- **Self-heals.** A deployment that recovers on its own — the image finally pulls, the crash loop settles — returns to Active within seconds instead of staying stuck on Failed.
- **Cleaner, correct events.** The events feed is newest-first, de-noised, plain-language, and scoped to the deployment.
- **Runtime view stays up.** The runtime panel loads without per-request cluster calls and keeps showing the last-observed state (rather than erroring) when a cluster is briefly unreachable; a failed toggle now correctly reads as a red "Error" instead of a green "Active".
- Deployments whose workload uses the recreate/OnDelete update strategy (e.g. the knowledge cache) no longer get stuck "deploying" with a healthy pod.

## Billing, natively

The settings **Usage** page is replaced by a native **Billing** page (personal and organization) with **Usage**, **Invoices**, **Credits & Commits**, and **Quotas** tabs showing real consumption, invoices (open as a PDF), and balances.

- **Save a card.** Accounts can add a credit card directly through a secure card form; the saved card is charged for hosted usage.
- **Usage no longer hard-blocks.** Metered consumption (compute, knowledge) no longer stops requests; per-account resource quotas (blueprints, builds, deployments, members, knowledge stores) still apply and can be raised from the Quotas tab.
- **Billing is admin-only.** Only organization admins and owners can view billing data or manage the saved card; the Billing nav item is hidden for regular members. Personal accounts are unaffected.

## AI Gateway: more models, native Anthropic path

- **New models.** The gateway adds Amazon Nova (`nova-pro`, `nova-lite`, `nova-micro`) and Mistral (`mistral-large-3`, `pixtral-large`), and gains documented streaming, embeddings, image input, and structured-output usage.
- **Native Anthropic API.** Claude Code and the Claude Agent SDK can now point at the gateway's `/anthropic` endpoint directly, alongside the OpenAI-compatible `/v1` path.
- **Base URL.** All gateway examples now use `${ASTRO_GATEWAY_URL}/v1`; the bare host returns 404. Existing agents pointed at the bare host must append `/v1`.
- Generating an `ast dev` key no longer intermittently fails when a key is rotated or a second user on the same account requests one.

## A dedicated Traces tab

Trace inspection moves out of Monitor into its own **Traces** tab with server-side search, a user filter, and sortable Date / Latency / Cost columns that work across the whole selected window without loading everything into the browser first. Slack user identities in trace rows now render with the same emphasis as Astro users.

## Insights: see your coding-tool usage

Local AI coding-tool usage (Claude Code today) now appears on the Insights page as its own source alongside deployed-agent spend, with a **Sources** filter across the chart, stat cards, agents table, and per-developer People view.

- Coding-tool traces are now correctly attributed to a developer by email and grouped into sessions in your observability views.
- Fixed coding-tool usage disappearing from the tables and Sources filter (and losing its brand color) for accounts whose usage was only very recent, and undercounting today's spend.

## Monitor external agents

New documentation walks through ingesting telemetry from AI coding tools with account-scoped ingest keys. The ingest-key dialog gains two off-by-default toggles to opt into collecting prompt/response text and tool inputs, reflected in the copyable managed-settings block.

## Chat improvements

- **Rename in place.** Rename a conversation by editing its title in the chat header; the history dropdown is now just navigation and delete.
- **Upload controls only when supported.** The file-upload paperclip, drag-and-drop, and Files tab appear only for agents that actually support files.
- **No more stuck "thinking" avatar.** A turn that finished while you were watching now recovers automatically instead of hanging until a watchdog fires; the underlying chat stream is resumable.
- The agent switcher no longer omits an agent you just deployed or activated, and no longer flickers messages when a brand-new conversation gets a fast reply.
- Your personal account's agents now sort first in the agent switcher.

## Deploy & Configure

- **Deploy any build.** Deploy and Configure now let you pick and deploy any readable published blueprint build — older, newer, or never-deployed — from a shared version picker showing commit title/SHA with Latest and Current markers.
- **Paused agents.** A paused agent on Configure now explains that it can't be redeployed and offers a single **Resume** button.
- Re-pushing a blueprint you've already registered no longer fails once you hit your blueprint limit — only genuinely new blueprints count against it — and quota messages now read "Blueprints" with usage/limit counts.
- Approving a quota-increase request now actually raises the account's limit; compute/knowledge options were removed from the quota-increase and deploy flows (handled by billing).

## Local development (`ast dev`)

- Each agent gets its own isolated data volume, so one agent's chat history and files no longer leak into another's.
- The embedded chat UI no longer prints a false "port is held" warning or leaves a worker squatting its port between runs.

## Admin console (Queen)

Flattened sidebar and a new per-account detail view showing billing status, resource usage/limits, pending quota requests, members, and cluster placement — with live health checks and one-click repair for billing/observability integrations, per-worker job history, and a guarded rename.

## Fixes

- The chat details panel's **Tokens** figure now shows real usage instead of always "0".
