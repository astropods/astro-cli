# Release — 2026-04-17.1

## GitHub Auto-Build for All Blueprints

GitHub-connected builds are now available to every blueprint owner — no experiment flag required. Connect a GitHub repo from the blueprint detail sidebar, and every push triggers an automatic build. The onboarding wizard now includes a GitHub import path: pick a repo, and Astro detects `astropods.yml` and `AGENT.md` automatically, kicking off the first build immediately.

Draft blueprints imported from GitHub show a preview card generated server-side from the repo's `AGENT.md`, so you can see what your blueprint will look like before publishing. Archiving a blueprint now disconnects the linked GitHub repo automatically.

## Knowledge Store Dashboard

Knowledge stores — previously CLI-only — now have a full management UI. The stores table shows provider icons, status, and is fully clickable. The detail page includes a settings side panel, infrastructure metrics (CPU, memory, storage, uptime), and an integrated log viewer with live tail support.

Creating a store walks you through provisioning stages with live K8s events, so you can watch your database come up in real time. The CLI also gained a `--tail` flag on `ast knowledge logs` for streaming.

## Overhauled Authentication

Sessions now last 30 days by default (previously 1 hour). Login and signup have dedicated routes with deep-link support — if you hit a protected page while signed out, you're redirected back after login. The CLI token refresh has been hardened: refresh tokens are persisted correctly, zero-expiry tokens are handled gracefully, and 401 responses trigger an automatic retry after refresh.

## Dark Mode

A new theming system (behind the `theming` experiment flag) adds light, dark, and system-follow modes. A three-button switcher appears in the user dropdown. Dark semantic tokens have been tuned for contrast and readability.

## Variable Bulk Import

Creating variables has been streamlined. You can now paste a `.env` block or add multiple variables at once through a bulk creation API with server-side validation. The variable row layout and inline descriptions have been polished.

## Per-Component Build Tracking

The build page now breaks down progress by component — agent, tools, models, and ingestion — each with its own status pill and collapsible log section. Build logs are persisted to the database (up to 512 KB per component) and served from there, with a fallback to live K8s logs for in-progress builds.

## Fixes

- Deployment detail tabs (Variables, Domains, Events) are now hidden when they have no data
- Archived blueprints no longer count toward your quota
- Dashboard org switcher responds correctly when clicking personal account
- First GitHub build no longer fails with a 404 — ECR repository is created automatically
- Loki live-tail now extracts log levels correctly via `detected_level`
- Heart and share button hover states no longer flash on re-render
- Blueprint breadcrumb shows account name as a clickable link
- Log viewer toolbar layout polished; live-tail button shows play/pause state
- Sort select background matches search input in light mode
