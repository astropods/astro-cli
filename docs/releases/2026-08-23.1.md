# 2026-08-23.1

## Billing and spend controls

An account can now cap what it uses, not only what it spends, and a new account
starts with a cap already set.

- **Set a limit on usage itself.** Compute and model usage each get their own
  warning and stop threshold, in their own unit: compute counts CU-hours, model
  usage counts US dollars of upstream cost. This is the one control that works
  on a plan that prices everything at zero, where a spend limit can never fire
  because priced spend is always zero.
- **New accounts start with a $20 spend limit.** It is the same limit the
  billing page writes, so the owner can raise, lower, or clear it. Existing
  accounts keep whatever they have.
- **Raising a limit restarts the account when the numbers allow it.** A stopped
  account restarts only once every limit it set is above what the period has
  actually counted, so lowering a cap under current usage leaves it stopped
  rather than restarting it for a few seconds.
- **An account stopped by its own limit is told that.** It previously read as a
  payment problem and sent the owner to replace a card that was working.
- **An account with no starting credit and no card is stopped.** It could
  previously deploy and spend at the AI gateway with neither credit nor a
  payment method behind it.
- **An account with no billing contract is stopped and named as such**, instead
  of rendering a plan card for a plan it does not have.
- **The usage chart is readable.** Each metric gets its own chart, axis, and
  unit, so nothing is summed across units and a small series is scaled against
  itself. Every day carries a tick, so the current day is always labelled, and
  the colors follow the theme. Model usage previously drew black on a dark
  background and stacked into a bar measured in no unit at all.
- **Usage totals name their units.** Compute hours and dollars shared one
  unlabeled column, so a compute total read as sixteen times its actual charge.
- **Saving spend limits no longer looks stuck.** A successful save that came
  back with an empty body left the form unchanged and silent.
- **The spend warning email names the period it covers.** That line previously
  rendered blank.

## Insights

- **The page fills in for a new account.** Building 90 days of history took
  about 360 requests and roughly three minutes against a one-minute budget, and
  the job only saved its place at the end. It restarted from day one every time
  and never finished. It now fetches a month per request, saves progress as it
  goes, and completes well inside its budget.
- **Claude Code spend is counted once.** It was counted twice, once branded and
  once as unattributed usage, so a day with $1.1K reported $2.2K and every stat
  card, chart, and percentage on the page inherited the error.
- **Organization admins can open the Claude Code breakdown.** The gate admitted
  the owner only. Viewing one of your other organizations no longer drops you
  to your own row either.
- **A reader restricted to their own usage now gets charts restricted the same
  way.** The charts reported the account's work and personal split to someone
  not allowed to see who was behind it.
- **A reader with no linked dev-tool address gets an explanation** instead of an
  empty table.
- **The date window and the range picker are one control.** The resolved dates
  sit inside the picker ahead of the range chips, the Sources filter moves to
  the end, and the dates stay visible at every width.
- **Classification keeps the work it already paid for.** One failed day, one
  failed batch, or one prompt the predictor refused used to discard an account's
  whole pass, and inference is billed before results are stored. A fault is now
  scoped to the day, batch, or prompt that caused it. Separately, a day of
  prompts stopped timing out: a classifier call now carries 64 prompts instead
  of 256.
- **The roll-up stops retrying deleted accounts.** Those jobs retried forever
  and could not even record why they failed.

The Claude Code detail page stays behind the `prompt-classification-stats`
experiment, off by default.

## Deploying and running agents

- **A crash-looping agent stops flipping between Running and Failed.** It
  alternated about once every two minutes for as long as the loop lasted, and
  each flip wrote an event row and restarted compute billing, so the event feed
  filled with noise and billable minutes were dropped. A recovered container now
  has to complete a five-minute run before the deployment reads healthy, and
  billing keeps its anchor across a failure and recovery.
- **A pod that is still starting no longer reads "Error."** It read "Error" with
  a red "Starting up" line beneath it, which contradicted itself during normal
  startup.
- **The deploy status and action panels follow the theme.** Some of their colors
  came from raw palette values and did not flip between light and dark.
- **An agent deployed from someone else's public blueprint gets its avatar.**
  The backfill looked the image up under the deploying account rather than the
  blueprint's owner, so a popular public blueprint produced one warning per
  account that deployed it, on every run, and none of them ever got an image.

## Fine-grained access

Both surfaces stay behind the global switch and the organization's Fine-grained
access experiment. Neither ships a customer frontend yet.

- **Deployment access APIs.** Inspect direct and group-derived access, request
  Viewer, Builder, or Admin for an organization member, and revoke that member's
  direct role. Requests return `202 Accepted` with a status of `pending`,
  `retrying`, or `synced`, and a background reconciler applies them.
- **Organization group APIs.** Manage WorkOS groups and their members, and
  assign a group a deployment role without the browser calling WorkOS. Listing
  groups is open to organization members for discovery; lifecycle and membership
  changes stay owner-only.

## Evals

A dataset's single fixed judge gives way to a set of independent evaluators.
Each one answers a single question and returns a typed value, so a result points
at one fix rather than a score a reader has to interpret.

- **Six presets ship in the default set:** exposed PII, leaked credentials,
  disclosed system instructions, unnecessary tool call, claim grounding, and
  user sentiment. They target defects a builder cannot check by hand across
  thousands of traces.
- **A job runs the set against one trace** and records each evaluator's result
  on its own, so one failure costs only its own result. A retry redoes only what
  failed, and two requests for the same trace join one run.

Nothing reaches this yet. There is no endpoint and no automatic enqueue; the job
is triggerable from the admin console only.

## Where agents run

Groundwork for an account that may deploy to more than one region. An account
now holds a set of allowed regions rather than one pinned region, operators
manage that set from the admin console, and image pulls are authorized against
it. Nothing a tenant touches changes: the deploy path still places agents
exactly as it does today, so no agent moves and no workload restarts.

## CLI

`ast billing get`, `ast billing status`, `ast billing invoices`, and `ast
billing set` read spend, credit, and billing status, and write limits, from the
terminal. `ast billing set --metric compute|gateway` writes the usage caps this
release adds.

### Billing

- **#2056** (`feat/billing-usage-controls`): the unlimited plan rates every
  product at zero, so priced spend is always zero and no spend control fires.
  Controls are therefore expressed in each meter's quantity. `usage_limit_active`
  is separate from `alert_active` because the two exits differ: a spend alert
  ends on the provider's spend edge, a usage cap on the quantity edge, an owner
  edit, or a period roll. `SignalUsageLimit` is deliberately not exempted on the
  unlimited plan, unlike `SignalCreditsExhausted`. Metric ids are resolved by
  matching the billable metric's event-type filter against `deployment_compute_usage`
  and `ai_gateway_llm_usage`, cached per process, and only a complete answer is
  cached. Recovery does not wait on the provider: the write endpoint clears the
  latch and reconciles workloads, and lifting is measured against period usage
  rather than the provider's `in_alarm`, which still reports on the archived
  alert straight after a write. A failed lift returns 200 with `limit_lift_failed`
  so the client keeps Save enabled. `not_provisioned` outranks every other
  reason; provisioning writes it on success and failure, and the billing read
  reports the gap without writing. `CustomerPlan` reports plan and coverage
  separately so an unrecognised package does not read as "no contract". A
  quantity threshold travels unrounded beside the envelope's minor-unit amount.
- **#2074** (`billing-default-spend-limit`): `BillingProvisionWorker` seeds one
  Metronome customer alert at 2000 cents, gated on `IsBillingProvisioned` before
  the stamp lands, so an operator credit grant re-running provisioning cannot
  reimpose a cap the owner cleared. A failed seed blocks the stamp, which keeps
  the account in the hourly sweep. Unlimited accounts are skipped. Distinct from
  the $20 monthly gateway budget on the Bifrost customer, which caps at admission
  and overshoots under concurrency.
- **#2069** (`fix/gate-accounts-without-credit-or-card`): `computeStatus` already
  suspended on credits gone plus no card, but `credits_exhausted` was raised only
  by `alerts.low_remaining_contract_credit_balance_reached`, which cannot fire
  for an account with no balance. Provisioning also applied `credits_granted` to
  every plan, clearing the latch. The latch now follows the plan. Affected
  accounts are those whose creator had already spent their single per-person
  claim.
- **#2067** (`fix/billing-usage-chart`), **#2064** (`fix/billing-usage-total-units`):
  the chart stacked `cu_hours` and `cost_usd` into one bar on one axis. Its
  palette of eight had five variables absent from the theme, and an undefined
  fill falls back to SVG black. One panel per metric, `--color-primary`,
  `--color-popover` for the tooltip, and a tick per day of the month. Totals
  render each metric's own unit; an unrecognised metric renders a bare number
  rather than borrowing another's unit.
- **`fix/spend-controls-empty-save-response`**: `SpendControls` scanned
  `Promise.allSettled` results for `limit_lift_failed` by reading the field off
  each fulfilled value, which threw when a save resolved to nothing. A bodyless
  response now reads as "not reported as failed".

### Insights and classification

- **`fix/insights-rollup-budget`**: the producer's fetch unit becomes a window of
  up to `MaxDaysPerWindow` (30) days using Langfuse's `timeDimension: day`, while
  storage stays per day, so 360 requests become 12. The count and cost/token
  queries join on a group key that now includes the day, otherwise the same
  `(tags, userId)` on different days collides. `RollUpRange` takes an explicit
  day list, since a range query returns only days with activity and a day whose
  spend dropped to zero would keep a stale row. New `RecordProgress` moves the
  watermark without clearing `last_error` or resetting `consecutive_errors`,
  which `Advance` does. Worker timeout is 15 minutes, retries cap at 5 instead of
  River's 25, and the failure write runs on a detached context because the most
  common failure is the deadline itself.
- **#2097** (`fix/insights-devtool-double-count`): `RollUpDevtoolsDay` filters the
  traces view to `claude-code` and writes `source='claude-code'`; `RollUpAgentsDay`
  queried the same view unfiltered and also wrote those traces under
  `source='agents'` with an empty `deployment_id`. The agent grain now skips a
  trace tagged with a registered dev-tool source, matched on the returned `tags`
  arrays rather than as a negative Langfuse filter. The model grain still reads
  observations unfiltered and has no reader.
- **#2100** (`fix/insights-scoped-charts`): the actor restriction moves into SQL
  on the daily aggregates, so a restricted reader never has other actors' rows in
  process. Elevation moves from `org:admin` to `org:manage`, which both `admin`
  and `owner` carry. When the session is scoped to another organization, the
  caller's role in the account's organization is resolved from WorkOS instead of
  read from the session claim. The unresolved-viewer state now keys off whether
  any address on the account resolves to the reader, rather than an actor key the
  handler always populates. Experiments are addressed by slug against a registry
  carrying the stored key, audit label, organization-only flag, and any extra
  permission, which keeps fine-grained access on `org:admin` while the route
  group moves to `org:manage`. Also removes `handlers/localseed_test.go`.
- **#2060** (`fix/insights-rollup-deleted-account`): `ListAccountIDs` joins
  `account_langfuse` to live accounts, closing the recurring fan-out. `GetByID`
  wraps `account.ErrAccountNotFound`, the producer translates it to
  `insightsrollup.ErrAccountGone`, and the worker skips before any write to
  `insights_rollup_state`, whose row is already gone after a hard delete.
  Distinct from the auth-failure skip, which must keep `consecutive_errors`
  climbing.
- **#2066** (`fix/classification-resilience`): each axis persists before the next
  runs, a classifier call returns completed batches alongside the failing one,
  and a partial trace fetch returns the pages it read. `classified_through` and
  `backfilled_from` advance only over the unbroken run of completed days, which
  also closes a hole where the budget path claimed unprocessed days. Backoff arms

  work plus roughly 40ms of HTTP.
- **`debug/insights-rollup-tracing`**: the worker logs its plan (watermark, day
  count and range, attempt, budget) before starting, each day's duration with

  returned a verdict and fails when none did. A partial unique index over

  with a lower ceiling. Known gap: the worker creates the run row itself because
  it needs the trace timestamp, so a pre-row failure on a later attempt can leave
  a run in progress; the endpoint closes this by creating the row at enqueue time.

  `GetDecrypted`, `decryptSecretKey`, and `ErrCredentialsDecrypt` are gone, and
  `EnsureProject` no longer takes a KMS ARN or client, which is what let the
  deploy path silently take the plaintext branch while the ingest-key path took
  the encrypted one. astro-otel's `internal/envelope` is deleted.
- **#2057** (`fix/langfuse-api-key-hard-delete`): Langfuse's `api_keys` has no
  `deleted_at`, so `DeleteProject`'s soft-delete rolled back the transaction and
  stalled every account purge behind it. Keys are hard-deleted, which is also the
  only thing that revokes them, since Langfuse looks up `fast_hashed_secret_key`
  without filtering a delete marker. The project keeps its soft delete and both
  statements stay idempotent.
- **`Give every log message one shape`**: every astro-server message becomes
  `component: lowercase phrase` with variables in structured fields, failures
  naming the subject first, one colon owned by the component prefix, and
  identifiers keeping their case. The rule is in `agents.md`.
- **`Notice when a backfill scan stops early`**: the backfill workers stop on an
  empty batch, and a row-iteration error ended the loop the same way, so a
  truncated pass logged "completed". Each loop reads `rows.Err()`: the avatar
  workers log and give up the pass, the provider worker returns the error for
  River to retry.
- **`Log the status a failed write was aiming for`**: the four deployment-failure
  sites logged "mark deployment as failed failed". The status becomes a
  structured field under one constant message, `update deployment status failed`,
  with a reason field distinguishing the partial-failure site.

### Docs

- **#1902** (`docs/agent-controlled-sandbox`): adds
  `docs/05-architecture/agent-controlled-sandbox.md` and
  `docs/06-plan/agent-controlled-sandbox-plan.md`. Build rather than resell,
  because reselling puts the one place customer code executes outside our
  infrastructure. Adopt E2B's `envd` protos over ConnectRPC so framework
  providers work against us with a base-URL change. Placement is the deployment's
  own namespace on gVisor, with the control plane out of the data path. Egress is
  four independent layers, IPv4 only. Auth reuses the deploy token; the
  per-sandbox token is an HMAC because envd compares a fixed string. Metering
  reuses CU-hours integrated over row timestamps rather than sampled. Delivery is
  sequenced by what cannot be retrofitted, with gVisor on from M1 and egress
  arriving in five stages starting observe-only.
