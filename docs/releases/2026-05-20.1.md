# Release — 2026-05-20.1

## Multi-Region Clusters

Astro can now route deployments across multiple Kubernetes clusters. The cluster the process boots into is the **primary** (configured from env vars, same as before), and any number of **additional** clusters can be registered into a new `clusters` table. Deploy specs and the deploy form accept an optional `cluster_id`; deployments without one continue to land on the primary. Cluster health is checked synchronously at deploy time — pointing at a missing or disabled cluster returns a 400 with an actionable message instead of failing asynchronously. Undeploys against a permanently-unreachable cluster fail open so the deployment can still be torn down, while transient errors stay retryable. Every read path (list, single deployment, GitHub build logs, probes, knowledge) resolves the right cluster client per row. The new astro-queen Clusters admin page is the canonical UI for registering, enabling, disabling, and deregistering clusters; the primary cluster is read-only.

## Blueprints Search

The Blueprints page has a real search box with debounced query, page-size tiles (10/20/50), and "Showing N of M" with a Load more button. Server-side, `GET /api/v1/agents` and `GET /api/v1/agents/:account` accept `q`, `tag`, `visibility`, `sort` (`name`/`newest`), `limit`, and `offset`. Non-members of an account always see only its public blueprints. The response shape gained a real `count` (total across pages, not the page length) and a `has_more` boolean.

## Insights and Activity Dashboard

A new `/insights` Activity page surfaces account-wide AI spend, requests, tokens, and active-agent counts with a time-range selector (7d / 14d / 30d / all-time, URL-anchored). Cost-over-time chart stacks by model with deterministic colors; a top-spenders table breaks down each blueprint's cost, requests, P95 latency, and dominant model. Period-over-period change percentages are computed server-side from parallel current/prior fetches. Monitor traces now show the WorkOS user behind each trace via an avatar + display-name badge that falls back to a raw id only when the user can't be resolved. The pod detail panel gets a maximize/minimize toggle for full-width inspection.

## Slack and Messaging Adapters

Slack `observe_channel_ids` is now a first-class spec field — list channels whose top-level non-mention messages should be forwarded to the agent. Adapter configs gained an inline-map passthrough so any new sidecar option can be set in `astropods.yml` without a spec release. The deprecated `allowed_user_ids` field renders with a strikethrough label and tooltip directing users to grants. `/api/v1/deployments/authorize` now returns the resolved WorkOS `user_id` on allow, including Slack→WorkOS resolution through the existing identity mappings; deny responses are unchanged. Messaging sidecar `LOG_LEVEL` is configurable per-project via `dev.interfaces.messaging.log_level`; local dev defaults to `debug`. A new smoke test validates the public Discord invite link.

## App-Wide Loading UX

Cross-page and account-switching transitions use a thin top progress bar (GitHub-style) instead of full-page skeletons. Pages stay mounted across navigation; previous data is shown until the new query resolves and atomically swaps in. The active account is now backed by a `Secure` cookie validated server-side, eliminating the SSR hydration flash on first paint. Legacy `astro:default-account` localStorage values auto-migrate on next load. Sensitive endpoints (knowledge credentials, audit log) still flush on account change.

## Account Profile

Public account profiles are now responsive — below `md`, the sidebar stacks above the tabs and the page scrolls normally; above `md`, the sticky sidebar/tabs split is preserved. Tab toolbars wrap on narrow screens. Org admins can access the internal-only view of org profiles (previously gated to the user themselves). Handleless members are filtered from member lists, and the `?visitor` preview toggle now correctly hides Members and Agent-count from owners. Profile navigation feels instant: the loader only awaits the account record itself, and blueprints/deployments/hearts stream in via skeletons.

## Deploy Form and Vault

Inline "+ New" variable creation works from the Slack adapter again — the account name now propagates through the picker chain. Vault auto-fill of `{{secrets.NAME}}` no longer races the variable list on first deploy; the effect waits until vault entries are confirmed loaded before binding. Adapter-injected variable refs (most notably Slack bot token) are preserved on redeploy instead of clearing the field. The deploy error banner moved directly above the action bar (always in view) and now uses the semantic `--error` token in light and dark mode. Agent pod URLs in the Domains panel are deduplicated.

## Knowledge and Build Pipeline

The redundant `persistent` flag is removed from `astropods.yml` — persistence is now derived from whether a mount path exists. Providers persist when `mount_path` is set; containers persist when `volume` is set. This is a breaking spec change (see Migration). Components with `container.build` no longer need a `container.image` — the registry image name is synthesized from `agentName` and the component kind/name. Structural spec problems (missing image+build, bad provider lookup, invalid trigger) now hard-fail at registration time and surface in the build log instead of producing zombie deployments. Integration providers are looked up under `integrations` (was wrongly `tools`).

## Container Environment

Every deployment container now sees `ASTRO_AGENT_ID = <deployment-id>` (alongside the existing `ASTRO_DEPLOYMENT_ID` collector var). Agents with exposed endpoints additionally receive `ASTRO_EXTERNAL_AGENT_URL` — the externally-resolvable public URL, distinct from the cluster-internal `ASTRO_AGENT_URL`/`ASTRO_AGENT_HOST`. The host is byte-identical to the ingress host (uses the same resolver).

## CLI and Local Dev

`ast project` (bare, no subcommand) accepts `--env` again. `ast dev stop` and Ctrl+C cleanup now remove orphaned one-off ingestion containers. `moon run astro-server:dev` properly kills its child air/server/fakeopenmeter group on Ctrl+C, so the next start no longer fails on `:8080` already in use. The local-dev fakeopenmeter binary is gone — a new `scripts/bootstrap-openmeter.sh` seeds the real OpenMeter instance idempotently. astro-queen Plans admin gains a migrate-subscribers dialog that uses OpenMeter's atomic migrate endpoint (close+restart in one step, preserves billing anchor).

## Docs, Theme, and Brand

Docs adopted the indigo brand (replacing the old teal), with dark mode fixed to a hex value Fern actually renders. The community link in docs swapped to a Discord invite. BETA labels were stripped from logos. A new `@astropods/brand-icons` package centralizes integration icon SVGs with separate light/dark sources, processed through a normalization pipeline. The `@astropods/theme` package bumped to `0.1.2`, exporting the new slate scale that downstream playgrounds were breaking on. Knowledge store screens were polished for dark mode with semantic tokens.

## Migration

| Change | Action |
|---|---|
| `persistent` flag removed from spec | Delete `persistent: true` lines from `astropods.yml` — derived from mount path now. `persistent: false` on a provider with a mount path has no replacement (switch to container mode without a `volume:`). `ast spec validate` errors on lingering keys. |
| Agents list response shape | `count` now means total matching rows, not the page length. Clients that relied on the old meaning should switch to `count` + `has_more`. |
| Observability summary response | Root-level `total_traces` / `input_tokens` / `output_tokens` replaced by a `totals.*` object; `from`/`to` query params required for change-vs-prior-period math. |
| Smoke tests | Moved to `apps/tests/smoke/`. `ASTRO_ENV` env var is now required (`dev`/`preview`/`prod`); run `moon run tests:smoke`. `ASTRO_TEST_USERNAME` is gone (per-env defaults). |
| Local OpenMeter | `fakeopenmeter` deleted. Set `OPENMETER_URL` in `.env` and run `scripts/bootstrap-openmeter.sh` once after `docker compose up`. |
| astro-theme version | Downstream consumers (e.g. `modules/playground`) must bump to `^0.1.2` for the slate palette. |
| `@astropods/brand-icons` consumers | Icon SVGs are now stripped of root `width`/`height` and inline styles. Style at the call site. |

## Appendix

**Commit range:** `34e5e8ce..7dee6b23`

**Multi-region clusters**
- New `clusters` table (`id`, `region`, `eks_cluster_name`, `eks_cluster_endpoint`, `enabled`, timestamps); `deployments.cluster_id` nullable varchar(64), FK `ON DELETE RESTRICT`. Atlas declarative diff drives DDL.
- New `internal/clusterstore` package: `Register`, `Get`, `List(enabledOnly)`, `SetEnabled`, `Deregister`, `ValidateID` (DNS-safe). Typed errors `ErrNotFound`, `ErrAlreadyExists`, `ErrInUse`.
- `k8s.ClusterClient` singleton replaced with `k8s.Registry`. Primary cluster (one per process) built from existing env vars (`EKS_CLUSTER_NAME` / `K8S_MASTER_URL` / `AWS_REGION` or `KUBECONFIG` / `KUBE_CONTEXT`); never materialized as a DB row. Additional clusters cached on `Get(ctx, id)` from `clusters` rows.
- Spec gained optional `target.cluster_id`. `SaveDeploymentParams.ClusterID`; `nilIfEmpty` stores empty as NULL. Validated against `clusterstore.Get` in deploy handler.
- `EffectiveClusterID()` is the routing key for River workers. River `riverqueue.Config` carries `*k8s.Registry`; deploy/undeploy/wakeup/GitHub build job args include optional `cluster_id` JSON. Reconcile/knowledge workers use the registry; knowledge K8s touchpoints stay primary-only.
- HTTP handlers resolve k8s clients per `deployments.cluster_id` via new `deploymentClusterClient` helper. `ListDeployments` enrichment goroutines resolve their own client per row (fixes shared-primary bug). Single-deployment routes return 404/503 on missing/disabled additional clusters; list falls back to DB-only entries. Knowledge, GitHub build logs, probes, admin gRPC stay on `registry.Default()`.
- `clusterHealthForDeploy` calls `k8sReg.Get` + `CheckHealth()` and returns `400 cluster is unhealthy` before `prepareDeployment`. Public `k8s.PublicClusterHealthDetail` in API. Undeploy fail-open narrowly via `k8s.IsPermanentClientResolutionError`; transient errors stay fail-closed.
- Admin gRPC: `RegisterCluster`, `EnableCluster`, `DisableCluster`, `DeregisterCluster`, `ListClusters` delegate to `clusterstore`, call `Refresh` after writes. Mutations on `primary` return `InvalidArgument`. `Registry.List` synthesizes a read-only `primary` entry plus DB rows; each `RegisteredCluster` includes `healthy`/`health_error`.
- astro-queen `/admin/clusters` page with HTTP proxy at `/api/admin/clusters` (5 routes) forwarding to admin gRPC. React `ClustersPage` with TanStack Query hooks and `AlertDialog` for destructive deregister.
