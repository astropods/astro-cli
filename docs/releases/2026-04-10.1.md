# Release — 2026-04-10.1

## GitHub-Connected Builds

Connect a GitHub repo to a blueprint and pushes will automatically build and deploy your agent. Build logs stream live in the sidebar while the job runs. Rapid pushes cancel any in-flight build so you're always deploying the latest code. A repo can only be linked to one agent per account.

## Require Authentication on the Messaging Interface

Deployments with a web interface can now require users to log in before accessing it. Enable the "Require authentication" toggle in the deploy form. Requires `MESSAGING_OIDC_*` environment variables to be set on the server.

## Playground Bundled into Messaging

The standalone playground is removed. The messaging container now serves the chat UI directly. `ast dev` handles this automatically. If you were running the standalone playground container, remove it and set `WEB_SERVE_PLAYGROUND=true` on the messaging container instead.

## Other Features

- **Pin a default org** — star an organization in the dashboard to make it your default on load
- **`ast config --save`** — export your stored config vars to a `.env` file
- **Create variables inline** — new variables can be created directly from the variable picker when setting up a deployment

## Fixes

- Messaging interface no longer disappears and reappears on each deploy
- Auth settings are preserved when editing an existing deployment
- Messaging expose is enabled automatically when the web adapter is selected
- Variable reference chips pre-fill correctly when a template variable already has a value
- Deploy error panel now shows specific validation details

## Migration

| | Action required |
|---|---|
| Playground | Remove standalone container; set `WEB_SERVE_PLAYGROUND=true` on messaging |
| GitHub org-scoped connections | Disconnect and re-link your repo once |
| Messaging ingress hostname | Changes on next redeploy; old hostname cleaned up automatically |
| Auth on messaging | Set `MESSAGING_OIDC_*` env vars on the server to enable the toggle |
