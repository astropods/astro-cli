The Astropods Spec (`astropods.yml`) is a declarative YAML format that describes the topology of an AI agent — its container, model dependencies, knowledge stores, tool services, and data ingestion pipelines. Build tools and deployment servers consume this spec; it intentionally excludes runtime, orchestration, and deployment-environment concerns.

## What the spec declares

- **Agent container** — Pre-built image or build-from-source configuration
- **Models** — LLMs, embedding models, or any inference API the agent uses
- **Knowledge stores** — Vector DBs or other retrieval backends
- **Tools** — HTTP APIs, MCP servers, or services the agent invokes
- **Custom providers** — External API services that require credential injection
- **Ingestion pipelines** — Data ingestion with trigger semantics (schedule, startup, manual, webhook)
- **Dev overrides** — Local development settings for `ast dev`

## Provider binding

Components (models, knowledge, tools) use a unified **provider binding** scheme. Each entry operates in one of two modes:

- **Provider mode** — Reference a platform-managed service (e.g. `ollama`, `anthropic`, `qdrant`). The platform either deploys a self-hosted container or injects cloud API credentials.
- **Container mode** — Full control over image, port, and configuration via a `container` object.

These modes are mutually exclusive. Authors can mix managed and custom components within a single spec.

## Top-level structure

A conforming spec includes:

| Field       | Description                                      |
| ----------- | ------------------------------------------------ |
| `spec`      | Version identifier (`package/v1`)                 |
| `name`      | Unique agent name                                |
| `meta`      | Description, tags                                |
| `agent`     | Container image or build config                   |
| `models`    | Model entries (optional)                          |
| `knowledge` | Knowledge store entries (optional)                |
| `tools`     | Tool service entries (optional)                   |
| `providers` | Custom provider entries (optional)                |
| `inputs`    | User-supplied inputs at deploy time (optional)   |
| `ingestion` | Data ingestion pipelines (optional)                |
| `dev`       | Local development overrides (optional)            |

## What the spec does not cover

Resource limits (CPU/memory), observability, rate limits, budgets, security policies, deployment region, and interface routing (Slack, web) are deployment-time concerns configured separately.
